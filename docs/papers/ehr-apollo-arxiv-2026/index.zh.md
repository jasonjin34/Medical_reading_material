# A multimodal and temporal foundation model for virtual patient representations at healthcare system scale

> **文献键** `Zhang2026_260418570` · **来源** arXiv preprint(2026) · **类别** ehr · **相关度** medium · **获取** open
> **链接** <https://arxiv.org/abs/2604.18570> · `status: complete`

## 一句话
APOLLO(Mahmood 组):在 Mass General Brigham 17 家医院 33 年、**720 万病人、253 亿条医疗事件、28 种模态**(结构化码、化验、生命体征、用药、病程记录与报告文本、病理/血涂片图像)上做掩码预训练的多模态时间 Transformer,把整个就医历程压成一个「虚拟病人」向量;冻结向量 + 线性 Cox 头在 140 万人测试集的 261 个预后任务和 61 个检索任务上大幅超过年龄-性别基线。

## 研究问题
EHR 是现代医学的记录系统,但数据被模态孤岛割裂,且维度极高、稀疏、不规则采样。已有纵向 EHR 基础模型大多**只用结构化数据**(诊断码、化验),因为有现成本体和离散 token 建模;而疾病进展的细节、医学推理、新型生物标志物常常只存在于自由文本和影像里。已有工作也多基于经过大量清洗的公开数据集(如 MIMIC-IV,仅 ICU)。问题:能否在一个**真实、未经精修、全科室**的医疗系统数据上,把结构化 + 文本 + 图像的完整纵向病历统一成一个时间感知的病人表示,并证明它在发病、进展、疗效、不良事件、医院运营等大量任务上通用?作者明确把这类比为「virtual cell」—— 多模态统一表示捕捉系统动态。

## 方法
**Tokenization**:结构化数据 → 离散 token(每个 ICD 诊断、每个 RxNorm 成分为一个 token;数值测量为 (代码, 分位数 bin) token;分类测量为 (代码, 规范类别) token),共 **235,768 个**可学习嵌入的结构化 token;生命体征/flowsheet 名称用 Qwen-32B 与 LOINC 类别对齐。**非结构化**用冻结的现成编码器:所有临床文本用 **GatorTron-base**(超长文本分块后取平均);全切片病理图像用 **TITAN**;血涂片用 **DinoBloom**;电镜与大体图像用 **CONCHv1.5**;非病理影像只用其诊断报告文本。**架构**:各模态 embedding 经模态特定投影层映射到共享空间;前置人口学 token(就诊末年龄、性别、种族)和 CLS;每个事件加上该时刻的病人年龄作为时间编码;encoder-decoder 结构。**预训练**:**模态特定 mask 的掩码 token 建模**(mask token 提示输出头应重建哪种模态);每步随机取 1,536 个连续事件窗口;AdamW,30,000 迭代,8×A100。**推理**:在序列末尾追加最后时刻 + 某模态 mask token,其隐状态即病人嵌入;多数下游任务用「诊断 mask」作提示,检索时可换成文本或图像 mask。**下游**:冻结嵌入 → PCA → Cox 比例风险模型(time-to-event,含右删失),报告固定时长阈值下的时间依赖 AUROC;对照为**年龄+性别 Cox 模型**。**可解释性**:个体层面 leave-one-token-out(LOTO)敏感性分析;人群层面 Integrated Gradients(在 Transformer 之前的输入上计算)。

## 数据
**MGB-7M**:Mass General Brigham 1992–2025 年,7,155,044 名病人、25,296,943,893 条事件、28 种模态、12 个主要专科;其中 flowsheet 229 亿条、化验 14.4 亿、生命体征 5.05 亿、病程记录 1.59 亿份、诊断报告 7,798 万份、图像 115.8 万张(含血液学与组织病理)。覆盖全部 14 个 ATC 用药大类和全部 ICD 章节。按 75:5:20 划分训练/验证/测试;**所有下游任务均来自 143 万人的测试集**。下游:95 个新发疾病任务(每任务 ≥6 万人,事件数 157–27,503)、78 个进展、59 个疗效、17 个不良事件、12 个医院运营任务、61 个检索队列。数据仅在机构审批 + MTA 下按个案共享。

## 主要结果
- **新发疾病(95 任务)**:74/95 显著优于年龄-性别基线(p<0.05);1 年全因死亡 AUROC **0.92**;3 年心衰 0.77→**0.88**;1 年急性心梗 0.68→0.82;3 年 **2 型糖尿病 0.61→0.85**;1 年痛风 0.74→0.83;1 年精神分裂症 0.65→0.92。
- **疾病进展(78 任务)**:53/78 显著;心血管类平均 0.65→0.75;**高血压→心衰 5 年 0.75→0.86**;卒中后 3 年生存 0.72→0.84;主动脉瓣狭窄后 3 年生存 0.72→0.83;哮喘急性加重 0.57→0.83;黑色素瘤 3 年生存 0.71→0.87。
- **疗效(59 任务)**:30/59 显著;内分泌系统用药平均 0.57→0.80;房颤用阿哌沙班后无卒中生存 0.69→0.81;氯沙坦/氨氯地平治疗高血压后无 MACE 生存 0.80/0.79;曲妥珠单抗 0.66→0.93。
- **不良事件(17 任务)**:12/17 显著;**NSAID 后急性肾损伤 0.80→0.91**;NSAID 后消化道出血 0.80→0.91;糖皮质激素后新发 2 型糖尿病 0.70→0.87。
- **医院运营(12 任务,balanced accuracy)**:9/12 显著;**住院透析依赖 0.65→0.97**;**急性肾衰 0.64→0.80**;脓毒症 0.66→0.79;30 天再入院 0.54→0.62。
- **消融(肿瘤进展任务集,正文为 28 个任务)**:APOLLO 平均 AUROC **0.735**;仅结构化数据 0.71(多模态 +0.025);同架构逐任务有监督训练 0.626;最近一份病程记录嵌入 0.615;年龄-性别 0.619 —— 预训练、多模态、时间上下文缺一不可。
- **检索**:61 个队列 Acc@5 全部高于「最近病程记录嵌入」基线;可检索到缺少肾移植 ICD 码(Z94.0)但实为肾移植的病人;支持自然语言入组标准和外部 TCGA 病理切片作为查询。
- **可解释性**:一例 CKD 3 年风险在高血压、血脂异常、2 型糖尿病记录后上升,并在 eGFR 降至 50 出头时再跳升;IG 在心衰→急性肾衰任务上突出肥胖、术后状态与衰老相关代理特征;作者明确把归因视为关联而非因果。

## 创新点
- 首个把**完整纵向病历(结构化 + 文本 + 图像,28 种模态)**统一成时间感知病人表示的医疗系统规模基础模型。
- 冻结现成单模态编码器 + 只训练时间 Transformer:原始数据不进入最终模型,降低 PHI 泄漏风险,且计算可行。
- **模态特定 mask 作提示**:同一模型可产出偏向诊断/文本/图像的病人嵌入,从而支持跨模态检索。
- 322 个任务的大规模评测框架(全部 time-to-event + 校准)。

## 局限
- **仅单一医疗系统**(MGB,共享 Epic 平台,美国东北部):只是系统内泛化,无外部验证 —— 与 CancerRiskNet 的跨系统跌幅相比,这是最大的未知。
- **对照只有年龄-性别**:没有与 ASCVD、CHA₂DS₂-VASc、Framingham 等临床评分或其他 EHR 基础模型正面比较。
- 观察性数据,预测为关联;「疗效」任务是在同一用药队列内做预后分层,**不能回答哪种药对该病人最好**(作者明确指出反事实任务尚待解决)。
- 冻结编码器、长文本简单平均;无可穿戴/生活方式数据。
- 预印本;代码「发表后」才开放,数据不公开。

## 与本研究方向的关系
**对 Sinai EHR 项目,APOLLO 是「如果把 Sinai 全部模态都用上会怎样」的上限参照**:规模(720 万人)与 Sinai 的「数百万病人」同量级,同样是美国学术医疗系统的真实、未精修数据,所以它的工程选择几乎可以逐条对照 —— 化验数值的分位数 token 化、用 LLM 对齐本地 flowsheet 命名到 LOINC、冻结文本/病理编码器、模态 mask 作提示、全部用 Cox time-to-event 评估。相比之下 Delphi/CancerRiskNet 只用诊断码:三者构成「仅诊断码 → 多模态」的梯度,Sinai 项目可以沿这条梯度逐步加模态并量化每步收益(APOLLO 的消融显示多模态比纯结构化只多 +0.025 AUROC,而预训练 vs 有监督差 0.109 —— **预训练规模比模态数量更重要**,这是 Sinai 早期优先级的直接依据)。**与心-代谢-肾方向高度相关**:它报告的最强结果里有大量肾/心代谢终点 —— 透析依赖(0.97 balanced acc.)、急性肾衰、NSAID 后 AKI、高血压→心衰、2 型糖尿病新发、心衰→急性肾衰、CKD 风险轨迹示例 —— 这正是实验室 Novo 资助的 cardiometabolic-kidney 基础模型/agent 要覆盖的终点集,可直接作为 Sinai 上的任务清单与目标数值。**与本方向(detect → model → revert)的联系**:作者自己把它类比为 virtual cell,并称其为「virtual patient」—— 这是病人尺度的 "model";它也用 TITAN/CONCH 嵌入病理切片,和 Plan A 的 H&E 侧编码器是同一族(Mahmood 组)。**它没做的正是 revert**:作者明确说疗效预测不是反事实,不能回答「换哪个药」—— 组织尺度的扰动/逆转建模与 EHR 尺度的虚拟病人之间,缺的就是这层因果接口。对 Plan B:LOTO + IG 的「可审计」解释,以及作者把归因标注为「关联/护理过程代理/假设生成」三类的做法,可直接转化为 agent 在 EHR 上作结论时的证据分级。
