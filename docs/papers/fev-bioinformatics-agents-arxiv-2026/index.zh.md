# Evaluating Agentic Bioinformatics through Function, Evidence, and Validation

## 一句话
这篇综述把「可检视的工作流轨迹」而非架构或最终答案作为分析单元,提出 Function–Evidence–Validation(FEV)框架:Function 记录 agent 实际演示了哪些工作流操作(F1–F6),Evidence 记录支撑动作与论断的可追溯来源(E1–E6),Validation 记录针对具体用例累积达到的保证等级(V0–V4 + 七个限定符);用它编码了 109 个生物信息 agent/近 agent 系统与 28 个基准 —— 规划与工具执行进展快,而可重放、溯源、外部验证与前瞻实验验证明显滞后(绝大多数停在 V3,仅 7 个到 V4)。

## 研究问题
LLM agent 已在规划、执行和解释生物分析,但流畅的回答、成功的工具调用和 benchmark 成绩都不能证明科学可信:系统可能执行了不合适的分析、检索了权威但无关的证据、保留了可重放却支持不成立结论的计算,或者只实验验证了其主要论断的一小部分。已有综述按应用、架构、能力来组织生物 agent,也提到了证据、可复现、鲁棒性和验证,但**没有一个在单个被评估工作流层面同时操作化这些维度的共同框架**。作者主张从「最终答案正确」转向「工作流正确」。

## 方法
**定义**:区分 bioinformatics copilot(辅助用户主导的分析)、workflow engine(如 Nextflow/nf-core,执行预定义流水线,能把不合适的流水线正确地跑完)与 agentic bioinformatics layer(自适应控制工作流);完整的 agent 层需同时具备:目标导向的多步可修订规划、有状态的工具执行、可检视的科学支撑(证据、trace、验证或升级记录);只满足部分的记为 agent-adjacent。**FEV 三维**(互补且不可互换):**Function**(描述性、非序数):F1 规划与任务分解、F2 角色分工与协调、F3 工具选择与工作流执行、F4 工作流状态维护与 trace 捕获、F5 自评与修复、F6 验证与升级(critic 只有改变了输出才算)。**Evidence**(非序数):E1 文献、E2 结构化生物知识、E3 生物测量与元数据、E4 软件与统计输出、E5 科学模型输出、E6 实验或临床观测;并给出每类的可追溯要求与主要局限(表 S4)。**Validation**(累积门槛,按用例而非平台):V0 示意性输出 → V1 已演示执行 → V2 可重放计算(输入、参数、依赖、中间产物、执行 trace 足以重建)→ V3 科学评估过的计算(在 V2 基础上有任务适当的科学检查)→ V4 前瞻实验评估(对 agent 生成的输出做与主要论断对齐的前瞻检验)。限定符:B 基准/基线、H 协议化专家评估、S 统计/不确定性、R 鲁棒性/失败分析、X 外部独立验证、P 前瞻实验、C 闭环实验改进。关键规则:限定符不能越过未满足的阶段 —— 没有 V2 可重放性就不能凭 benchmark 或专家评估给 V3;已发表的实验数据作为输入属 E6,不是 V4。

## 数据
结构化证据图谱:109 个 agent 或 agent-adjacent 系统条目 + 28 个基准/评测资源,9 篇论文同时属于两类,共 128 篇独立文献;覆盖基因组与基因编辑、单细胞与空间组学、蛋白组与蛋白设计、药物发现、计算病理与影像、通用生物信息自动化。检索 PubMed、Google Scholar、Semantic Scholar、arXiv、bioRxiv、medRxiv 及主要出版商平台,主要时间窗 2022 年 1 月至 2026 年 7 月,含预印本,并做前后向引用追踪。逐系统 FEV 编码见补充表 S1–S28,基准画像见 S29–S33。未报告或文档不足的能力不编码。

## 主要结果

- **整体格局**:规划、工具执行、工作流状态维护、自评/修复普遍存在;角色分工与显式验证/升级(F6)较少。证据以软件输出、结构化知识和回顾性生物数据为主,实验/临床观测(E6)是最少的证据类别。
- **验证阶段**:绝大多数系统为 V3,**只有 7 个达到 V4,没有 V0**;基准比较(B)与鲁棒性分析(R)是最主要的限定符,前瞻检验(P)与闭环改进(C)是例外 —— 闭环实验改进只出现在**一个**被编码的框架中。
- **领域差异**:工具执行与 trace 捕获在病理、药物发现和通用工作流中突出,在基因组学中报告较少;显式验证/升级在基因组学、蛋白工程、单细胞/空间分析中少见;外部评估集中于单细胞、空间与病理系统;前瞻检验集中于蛋白工程。
- **广度 ≠ 保证**:大多数系统实现了多个 Function 与 Evidence 维度,但仍停在 V3;更多 agent、工具、数据库或记忆模块可以扩大工作流,却不建立可重放性、验证或对主要论断的实验支持。
- **最大缺口**(1 − 领域内报告比例):前瞻实验检验与闭环改进最大;验证/升级、专家评估、不确定性分析、外部验证报告不均。
- **示例编码**(补充表):CellVoyager V3 [B,H,R,X],「未报告前瞻湿实验」;SpatialAgent V3 [B,H,R,X],「前瞻湿实验验证未建立」;Biomni V3 [B,R];OmicsNavigator(可审计空间组学假设验证)V3 [B,H,S,R,X],在**肾脏**和肺的 CODEX/IMC 数据集上评估。
- **基准建议**:三类基准互补 —— 结果导向、过程导向、领域校准;正确的终点不应在未调用所需工具、证据捏造或不可重放时得满分;基准报告应写明其结果**不能**支持的论断。

## 创新点
- **把工作流轨迹作为分析单元**,并把 agentic bioinformatics 定义为自适应工作流控制层(区别于 copilot 与 workflow engine)。
- **FEV 三维分离**:操作广度、证据可追溯性与科学保证互不替代;Validation 用累积门槛 + 非序数限定符表示。
- **「replayability gate」与「evidence–testing distinction」**:没有可重放就没有 V3;用过的实验数据 ≠ 前瞻检验。
- 128 篇文献的跨领域结构化证据图谱与工作流正确性议程(含最低报告标准)。

## 局限
- 编码完全依赖论文报告:未报告即不编码,比例描述的是综述样本而非全部文献,且受报告习惯影响。
- 是有方法学说明的结构化综述(检索库、关键词、纳排标准),但不是 PRISMA 式系统综述;文中未报告编码者间一致性检验。
- V 阶段是用例级的,同一系统不同任务可能处于不同阶段,跨系统比较需谨慎;作者明确不做排名。
- 是综述/框架论文,FEV 本身没有在真实工作流评测中被实证检验(例如 FEV 分级是否预测下游可靠性)。

## 与本研究方向的关系
这是 **课题 2 的「概念框架章节」最合适的引用**:它用生物信息学的语言说清了课题 2 要做的事 —— 从「答案对不对」转向「工作流对不对」,并把 claim-to-evidence(Evidence 维度的可追溯性)、rerun stability(V2 可重放性)、校准验证(限定符 S/H/X)和失败分析(R)放进同一个结构。具体可用之处:**(1) 给课题 2 的评测设一个明确的目标等级**:评估分析肾脏组学(snRNA/snATAC/Xenium)的 agent 时,至少要求 V2(可重放:数据 accession、元数据假设、参数、版本、中间产物、trace),再在 V3 上加 S(不确定性/校准)与 X(在 KPMP/Lake 等外部数据上独立验证);**(2) 证据类别表 S4** 中 E3「生物测量与元数据」的局限 —— 噪声、混杂、批次效应、元数据缺失 —— 正是课题 1「跨模态一致性区分伪影与疾病」要解决的问题:课题 1 的输出可以作为课题 2 中 E3 证据的**可信度标注**;**(3) detect → model → revert 的 revert 阶段**对应 V4 与 P/C:实验室有湿实验验证能力,意味着我们的系统有机会达到综述中罕见的 V4 [P],甚至 C(湿实验结果回传并改变下一轮提名)—— 这是目前全领域只有一个框架做到的闭环;**(4)** 综述指出单细胞/空间系统(CellVoyager、SpatialAgent)普遍缺显式验证/升级(F6)与前瞻检验,这正是 KidneyAnomalyBench + 课题 2 verifier 可以填补的定位。另外 OmicsNavigator 在肾脏 CODEX/IMC 上的评估值得跟进,作为与我们最接近的已有系统。
