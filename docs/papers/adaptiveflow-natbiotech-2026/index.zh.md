# AI-enhanced adaptive virtual screening of large libraries for ligand discovery

> **文献键** `Cecchini_2026` · **来源** Nature Biotechnology(2026) · **类别** drug-discovery · **相关度** high · **获取** open
> **链接** <https://doi.org/10.1038/s41587-026-03217-x> · `status: complete`

---

## 一句话
AdaptiveFlow 是一个开源(GNU GPL-2.0)的超大规模虚拟筛选(ULVS)平台:它把 Enamine REAL Space 2022q1-2 准备成 69 billion 个 ready-to-dock 分子、按 18 维分子性质切成约 1,200 万个 tranche(格子),再用 Adaptive Target-Guided Virtual Screen(ATG-VS)先用每格 1–10 个代表分子做 12 million 次 prescreen、只对最优的 tranche 做 primary screen(可选叠加一个主动学习式 ML 分类器),把穷举 docking 的成本最多降低 1,000 倍;平台集成约 1,500 个 docking protocol,在 AWS 上近线性扩展到 5.6 million vCPU,并在 FSP1 与 PARP1 上前瞻性地做出纳摩尔抑制剂(afi-FSP1-1 Ki 0.283 µM、iParp1 IC50 8.8 nM)与共晶结构。

## 研究问题
合成可及的类药小分子估计超过 10^60 个,而典型实验 HTS 只能筛几十万个;可购买的 on-demand 分子已从 2020 年的约 2 billion 增长到万亿量级(论文引用的估计是多家供应商合计可达 3 trillion)。ULVS 因此成为替代路线,但有三个硬约束:**成本**(穷举 docking 数十亿到数百亿分子即使在云上也不可承受)、**灵活性**(不同靶点类别需要理论基础不同、输入格式各异的 docking 算法,而平台往往绑死在少数程序上)、**可扩展性**(多数现有平台只支持 CPU,无法同时利用 GPU 与新兴架构)。瓶颈尤其出在 protein–protein interaction interface 与 allosteric site 这类浅、动态、边界不清的口袋上。论文要解决的是:在不穷举的前提下,如何**智能地把 docking 预算集中到对给定结合位点最可能出命中的那一小块化学子空间**,并把这件事做成可复用、也能服务 AI/ML 方法开发的开源基础设施。

## 方法
**三个模块**:AFLP(AdaptiveFlow Ligand Preparation,库准备)、AFVS(AdaptiveFlow for Virtual Screening,筛选引擎)、AFU(AdaptiveFlow Unity,把两者合成单一自动化流水线,既可 standalone 命令行运行,也可以 **API mode 直接被其他程序/ML 代码调用**;AFUparr 是 SLURM 上的并行版)。整个代码库从上一代的 Bash 重写为 Python。

**AFLP**:desalting、中和、立体异构体枚举、互变异构体生成、质子化态预测、最低势能 3D 构象计算、目标格式转换(支持 100 多种输出格式);输入支持 SMILES、SELFIES、氨基酸序列;外部工具逐步可换(ChemAxon JChem 18.20.0 / Open Babel 2.3.2 / RDKit,每一步都提供开源替代——上一代有些步骤必须用非开源的 ChemAxon);质量检查用 Open Babel 算 3D 势能、自动剔除势能过高(可能在准备过程中损坏)的分子,并可选用 **PoseBusters** 做构象合理性检查;为每个分子算 **28 个**理化性质/描述符(含 QED、logP),并**自动**把库重组成多维 tranche 矩阵(上一代要求输入已是 tranche 格式)。速度上用自写 Java 代码经 Nailgun 调 JChem(减少调用次数),并加了用户可调的超时参数以跳过异常慢的配体。

**18 维 tranche 矩阵**:从 28 个性质中挑 18 个作为维度(molecular weight、logP、hydrogen-bond acceptor/donor count、rotatable bond count、TPSA、molecular refractivity、logS、aromatic ring count / aromatic proportion、formal charge、positive/negative charge count、fraction of sp3 carbons、chiral center count、(double-bond)stereoisomer count、halogen atom count、sulfur atom count、Enamine compound class),每维离散成若干区间,理论上组合出 **24.4 billion** 个 tranche,REAL Space 实际只占据 **约 1,200 万**个;每个被占据的 tranche 平均 **5,600** 个分子,但占据度跨多个数量级(从只含 1 个分子的 tranche 到 **>10 million** 分子的 tranche)。配两个交互式 web interface(不同渲染框架),把 18 维投影到 2D 显示,同时用滑块在全部 18 维上独立选区间——等价于在 18 维里选一个超矩形,所选分子数实时更新,子集可直接送 AFVS 去筛。18 这个维数是"化学相关性 vs 计算可行性"的折中:维数再高矩阵会过稀疏。

**ATG-VS 四步**:(1) *Library decomposition* — 每个 tranche 选 1–10 个代表分子(用户设定;选 >1 时代表分子自动要求彼此多样);(2) *ATG prescreen* — 只 dock 这些代表分子(1 个代表/tranche ⇒ 全库 12 million 次 docking,比穷举 69 billion 少 **>5,000 倍**),可叠加基于 18 维性质的动态过滤(例如按靶点位点的性质手工设定准则)进一步减少;(3) *Selection of active tranches* — 按代表分子的 docking score 与 ligand efficiency 自动选最优 tranche,两种选法:逐个手动选 tranche(细粒度控制特定化学子空间),或取 18 个维度上各自表现最好的 bin 做**笛卡尔积形成超矩形区域**(hyperrectangle 法,得到"化学多样但有针对性"的子集);用户指定 primary screen 的分子总数,平台自动优先选代表分子表现最好的 tranche;(4) *ATG primary screen* — 把选中的 tranche 全筛(典型 1M–1B 化合物),并可选在格内先用 ML 分类器挑最有希望的分子。另有可选的第三阶段用更高精度(如加入受体柔性)重打分;三个阶段可全自动串起来。平台同时支持传统 funnel-type 多阶段筛选(先粗筛排名,再用更高 exhaustiveness 或不同打分函数重筛 top),阶段数任意;新库/专有库也能被 AFVS 准备成带代表分子的多维 tranche 矩阵以支持 ATG-VS。

**可选的 ML / active learning 层**:在 prescreen 之后、primary screen 之前,用一个全连接前馈网络过滤选中 tranche 里还没 dock 的分子。输入是 RDKit 2023.03.1 生成的 Morgan fingerprint(length 1,024、radius 2);标签来自 prescreen 的 docking score——最负的 top 25%(即第 75 百分位作决策边界)记为 "high-confidence binders" 正例,其余为负例,训练时对多数类下采样;结构 1,024 → 512 → 256 → 128(ReLU)→ 1 个 sigmoid 输出;Adam(lr 0.001)、binary cross-entropy、10% 验证集、patience 5 的 early stopping、最多 50 epoch、batch 256(通常更早收敛);超参经 prescreen 数据上的交叉验证做有限调优;实现用 PyTorch 2.0.1 并支持 GPU;整个模块集成在 AFU 里,**一个配置参数即可开启**。预测结合概率 >0.5 的分子保留去做完整 docking,这一步**通常把需要 dock 的分子数再减少 30–70%**(依靶点而定),同时保持或提高命中富集。因为每一轮筛选都产生新的带标签数据,这个循环可以**重复任意轮数**,用新 dock 的(以及可得的实验测定的)化合物重训模型、再选下一批,构成逐步把采样集中到最有希望区域的闭环主动学习。

**docking protocol 的组合学**:论文把 "docking protocol" 定义为 *sampling algorithm(pose prediction)× scoring function* 的一个具体组合;平台支持约 40 个 docking 程序(分三类:既做 pose 预测又打分的、只做 pose 预测的、只打分的),自由组合出**约 1,500 个 protocol**,通过单一命令行接口调用——用户不必逐个配置和学习多个 docking 程序。覆盖的配体/靶点类型包括 small molecule、peptide、protein(protein–protein docking)、DNA/RNA 与 covalent binder,部分程序还有显式溶剂/金属参数化等 "special features";ML docking 含 **DiffDock、TANKBind、EquiBind**;GPU 打分含 Gnina、NNScore 2.0、DeepBindRG、DeepAffinity;GPU pose prediction 含 AutoDock-GPU、QVina2-GPU、QVina2-W-GPU、Vina-GPU;MD 类重打分/精修含 **MM/PBSA、MM/GBSA 与 binding pose metadynamics(OpenBPMD)**;Vina 系的 pose 可选 PoseBusters 校验。QuickVina 2 被重新 profile(Intel VTune)后发现执行剖面很平(最耗时函数 <20% 运行时),因此改走编译器级优化:用 Intel oneAPI DPC++/C++ Compiler 2022.2.0.20220730 开自动向量化、过程间优化与放松浮点约束重编译,最终可执行文件比默认构建**快 18%** 且无精度损失(profile-guided optimization 没有帮助)。

**工程与云**:并行化分三层 —— collection(约 1,000 个配体一组,降低逐配体调度开销)→ subjob(原子计算单元,按 job 配置自动生成,约 30 分钟)→ work unit(以 job array 提交给调度器);批处理系统支持 **Slurm**(Google Cloud / Azure / AWS 皆可;用户给一个提交模板,AdaptiveFlow 运行时填入 job array、partition、memory 等变量,从而把工作流逻辑与集群配置解耦)与 **AWS Batch**(+ S3 对象存储、CloudFormation 部署、Docker 容器自动生成);使用 spot(可抢占)实例降低成本,并通过 AWS Batch 的 "spot-capacity-aware" 调度与短 subjob + 自动重跑来吸收抢占;支持 x86 与 **ARM** CPU(ARM 往往更便宜)以及 NVIDIA/AMD GPU。AFVS 输出可写成 **Apache Parquet**,从而被任何能读 Parquet 的查询系统使用(例如 S3 上的 serverless **Amazon Athena**),并有自动用 Athena 后处理 ATG prescreen、为 primary screen 准备输入的功能。

**FSP1 的湿实验链路**:先用 ancestral sequence reconstruction 重建人 FSP1 的四足动物祖先蛋白(序列同一性 72.5%,保留全部活性位点残基;E. coli 表达约 100 mg l⁻¹,Tm 62 °C,保留全部酶活,衍射质量好),解出 FSP1–FAD、FSP1–FAD–NAD⁺、FSP1–FAD–NAD⁺–coenzyme Q1 三个高分辨率结构,再以 **PDB 9IFT**(FSP1 + FAD + NAD⁺)为受体筛 coenzyme Q 位点:受体用 Maestro(Schrödinger)准备(去溶剂、补氢、pH 7.4 下修正质子化态、修正键级),用 AutoDockTools 1.5.7 转成 PDBQT。

## 数据
**化学库**:Enamine REAL Space,enumerated release **2022q1-2**(2022-11-15 获取),原始 **31,507,987,117** 个以 SMILES 表示的未处理分子,经 AFLP 准备(主要因立体异构体与互变异构体枚举)扩展到 **68.7 billion** ready-to-dock 分子(摘要作 69 billion)。组成:**137,000** 个已建立的建块 × Enamine 内部验证的 **167** 个 one-pot 合成方案;基于 2021 年 **386,000** 次实验反应报告的合成成功率 **82%**;**99%** 符合 Lipinski Rule of Five;**1,098,811,629** 个唯一 Murcko scaffold;**>62 billion(74%)** 至少含一个手性中心(所谓 "nonflat" 化学空间);**23 billion** 含卤素,其中 **17.4 billion** 含氟(适合不需同位素标记蛋白的 ¹⁹F NMR 结合实验)。作为对照,此前最大的公开 ready-to-dock 库(2018 版 REAL Database、ZINC20)各约 1.5 billion。格式:ready-to-dock 的 PDB、PDBQT、MOL2、SDF(每种格式压缩后约 **50 TB**,四种共约 **200 TB**;未压缩约 **2 PB**),外加 SMILES、**SELFIES**、Parquet。18 维矩阵本身仍很稀疏,大量未被占据的 tranche 被作者视为"值得前瞻性合成去填充的化学空间"。

**基准靶点**:10 个结构多样的蛋白,覆盖 kinase、phosphatase、GPCR 与 protein–protein interaction interface,图 4 标注为 **KRAS-G12V、CB1、PTPRB、JNK3、TLR8、PIK3CG、NTR1、MED15-KIX、KEAP1、RPTO**(确切身份与结构来源在 Supplementary Table 7,未读)。两套设置:(a) *test-based benchmark* — 从 Enamine 空间随机抽合成反应构造约 **5 million** 化合物子集,每个靶点用**不同的**随机子集以保证评测无偏;(b) *production-scale benchmark* — 整个 69-billion REAL Space。所有基准 docking 默认用 **QuickVina 2** 默认参数;另用 **Smina(Vinardo 打分)** 与 **GWOVina(柔性侧链)** 复跑,以检验 binning 策略对 sampling 算法与打分函数的敏感性。

**实验靶点、结构与测定体系**:FSP1(coenzyme Q 位点,受体 PDB 9IFT)与人 PARP1。沉积结构:FSP1 的 **PDB 9IFZ、9IFT、9IFY、9IFU、9IFW、9IG9、9QRT**;PARP1–抑制剂复合物 **PDB 8VYH**(催化域 + 水解形式的 iParp1,2.05 Å);FSP1 祖先序列 **GenBank PQ619396**。细胞/生化体系:FSP1 表达的 HEK293(cellular thermal shift assay)、T cell acute lymphoblastic leukemia 细胞系 **Jurkat**(与 ferroptosis 诱导剂 erastin 0.5 µM 联用,ferroptosis 抑制剂 liproxstatin-1 回救)、**BRCA1 缺陷三阴性乳腺癌**细胞(PARP1 clonogenic assay)。测定手段:NADH 氧化动力学(340 nm,pH 7.2;NADH 5–200 µM、coenzyme Q1 100 µM、FSP1 0.1–0.2 µM)、thermal shift、surface plasmon resonance(Kd)、间接 resazurin assay(IC50)、protein NMR、X 射线晶体学、定点突变与细胞 ADME。

## 主要结果
- **ATG-VS 的省算量**:1 个代表分子/tranche 的 prescreen 只需 **12 million** 次 docking 就"摸"遍 69 billion 的库,比穷举少 **>5,000 倍**;Discussion 的总账是 ATG-VS 相对穷举**最多省 1,000 倍**成本,再叠加 deep-learning docking 与 GPU 加速可额外提高 **10–100 倍**吞吐。
- **prescreen 的超参已经饱和**:比较 (1) 1 个代表 + exhaustiveness 1、(2) 10 个代表 + exhaustiveness 1、(3) 1 个代表 + exhaustiveness 10,三者在 top docking score 分布与各性质维度内的 tranche 排序上**结果相近**,因此作者认为多数应用用最便宜的设置(1 个代表、exhaustiveness 1)就够;只有在多阶段中加第二段高精度筛选时才值得提高 exhaustiveness。
- **test-based benchmark(5M 子集,10 靶点)**:三臂为 1M random、100K ATG、100K ATG+AL(后两者的 10 万次 docking **含 prescreen**,即只用了随机筛的 1/10 预算)。top-50 平均 docking score(kcal mol⁻¹):KRAS-G12V −11.83 / −11.95 / **−12.11**(该 5M 子集穷举最优 −13.11)、CB1 −13.93 / −14.14 / **−14.25**(−15.20)、PTPRB −9.37 / −9.60 / **−9.90**(−10.41)、JNK3 −12.08 / −12.37 / **−12.54**(−13.64)、TLR8 −10.38 / −10.55 / **−10.81**(−11.70)、PIK3CG −11.90 / −11.99 / **−12.25**(−13.82)、NTR1 −13.10 / −13.26 / **−13.58**(−14.69)、MED15-KIX −9.51 / −9.77 / **−9.96**(−10.48)、KEAP1 −11.30 / −11.49 / **−11.66**(−12.60)、RPTO −10.92 / −11.00 / **−11.19**(−12.11)。结论:**只采样 1/10 的分子就达到或超过随机筛 1M 的效果,且 ML 一步在十个靶点上一致地再好一点**。
- **production-scale benchmark(全 69B 库,不开 active learning 以减少开销)**:与 100 million 随机化合物的标准 ULVS 相比,ATG-VS(prescreen 为每 tranche 10 个代表 ⇒ 12 million 化合物,primary screen 规模在 10,000 / 100,000 / 1 million 间系统变化;Extended Data Fig. 6 的图注写 prescreen 为 11 million 代表化合物,Fig. 7 另有 100 million 对 100 million 的比较)在 top-50 docking score 上取得**相当或更好**的结果,而 docking 次数大幅减少;Extended Data Fig. 7 的图注更强调 ATG 的 top-50 对**所有**受试蛋白都明显优于标准 ULVS。
- **收益随靶点而异,但 binning 对 protocol 不敏感**:口袋复杂、特征丰富的蛋白——尤其是大片疏水表面 + 边界清晰的极性亚口袋的组合——从 ATG 优先化与 ML 增强中获益最大。换用 Smina(Vinardo)与 GWOVina(柔性侧链)复跑后,ATG-VS 的 speedup 与 enrichment factor 与 QuickVina 2 相当,top-50 的平均预测亲和力同样优于随机筛,说明**基于描述符的分箱与结合潜力的相关性在不同复杂度的 docking protocol 上都成立**。
- **扩展性**:AFLP 在 AWS 上用 **>5.6 million Intel vCPU** 并行准备 REAL Space,扩展行为"完全线性",用 spot 实例时**<0.1%** 的 CPU 小时因抢占中断;上一代平台只验证到 **160,000** vCPU。AFVS 与 AFLP 共享并行机制,扩展行为**预期**相同。这个量级意味着数十亿化合物的 ULVS 可以在**小时级**完成,传统本地集群需数周到数月。
- **FSP1 筛选与命中**:ATG prescreen(1 个代表/tranche ⇒ 12 million 次 docking)+ **10 million** 化合物的 primary screen(**未用 ML**);对 top 候选施加过滤(logP < 5、logS > −5、TPSA < 140 Å²、立体中心 ≤ 3,并排除问题官能团与预测毒性:致突变、生殖毒性、致瘤);最终从 **37** 个 cluster 中挑 **42** 个 SwissADME 零警示化合物向 Enamine 订购,**33** 个被合成并实测。thermal shift + NADH depletion 筛出 **2** 个(熔点位移 ≥1.5 °C 且 10 µM 下抑制 FSP1 氧化还原活性 ≥50%):**afi-FSP1-1 Ki 0.283 ± 0.05 µM(Kd 0.098 µM)**、**afi-FSP1-2 Ki 0.777 ± 0.22 µM(Kd 0.266 µM)**,与已报道的 FSP1 抑制剂相当或更好。CETSA 在 FSP1 表达的 HEK293 中给出 **2.8 °C / 3.1 °C** 位移,证明在细胞内结合人 FSP1。Jurkat 细胞对 afi-FSP1-1 + 0.5 µM erastin 敏感,活性与常用的 iFSP1 相当;单药到 10 µM 无细胞毒,25 µM 的促 ferroptosis 效应被 liproxstatin-1 完全回救。以 FSP1–afi-FSP1-1 复合物的 3D 结构为输入**再筛一轮**,返回 **20** 个 afi-FSP1-1 类似物并实验检验,其中 **4** 个有活性:afi-FSP1-3 Ki 0.520 ± 0.11、afi-FSP1-4 0.284 ± 0.07、afi-FSP1-5 1.000 ± 0.32、afi-FSP1-6 3.940 ± 0.71 µM(后两个分别以外消旋与非对映异构体混合物测定);它们共享一个 aromatic-amide-饱和杂环核心。细胞 ADME 指出 **afi-FSP-3** 是最适合继续做 medicinal chemistry 优化的候选。
- **FSP1 的机制洞察**:共晶结构显示所有抑制剂都占据 coenzyme Q 位点并置换 coenzyme Q1,其(酰胺)羰基氧与 flavin 的 N(3)H 形成氢键——与 ubiquinone 头部的作用方式同构——并通过一个水分子与 L323 的主链 NH 相连;Y290 与 F354(夹住 coenzyme Q 醌环的两个芳香侧链)夹住配体,F15 以疏水与 π 堆积作用参与;结合模式经定点突变验证,并与测得的 Ki 相关。NAD⁺ 的结合构象在有/无配体与有 coenzyme Q1 时完全一致,因此 afi-FSP1-1/-2/-3 对 FSP1 的 NADH oxidase 活性只有 **1/10–1/12** 的效力、afi-FSP1-4 完全无效;作者据此提出一个待验证的药理设想:**选择性抑制 quinone 还原活性而保留与氧的反应性,可能把 FSP1 从抗 ferroptosis 转为促 ferroptosis**。结构还直接说明 NAD(P)H 与 coenzyme Q 可同时以催化就绪的取向结合(与动力学的三元复合物机制一致),以及氧有足够空间接近 flavin N5——这解释了 FSP1 为何兼具 NAD(P)H oxidase 活性。
- **PARP1**:ATG prescreen 后做 **100 million** 分子的 primary screen,合成 **160** 个候选;两浓度酶学 HTS 找到 **7** 个抑制剂,其中 **4** 个(iParp1–iParp4)IC50 < 250 nM;**iParp1 IC50 8.8 nM**,与 FDA 批准药 olaparib 相当——而这完全来自纯虚拟筛选,**没有用任何已知抑制剂的知识,也没有做 medicinal chemistry 优化**。结构相似性分析显示部分命中与已知 PARP1 抑制剂共享关键 scaffold、另一些是不同的 scaffold 变体。protein NMR 的化学位移扰动确认直接结合活性位点并支持预测的 docking pose;X 射线给出 2.05 Å 的 PARP1 催化域–水解型 iParp1 结构。BRCA1 缺陷三阴性乳腺癌细胞的 clonogenic assay 显示 iParp1 与 iParp2 有选择性细胞毒性,但细胞活性偏弱(尤其 iParp1),原因被归为**水解导致的膜通透性差**。
- **与自家前作的对照**:作者此前发现纳摩尔 KEAP1–NRF2 抑制剂需要无偏地筛 **1.3 billion** 个分子;这次 FSP1 的 ATG 引导筛选只用 **22 million** 次 docking instance 就取得可比的成功。

## 创新点
- **把"筛哪些分子"变成一个显式的、低维的决策问题**:用 18 个理化性质把 69 billion 的库离散成约 1,200 万个 tranche,再用代表分子的 docking score 给每个 tranche 打分——相当于为每个靶点生成一张"化学空间活性热图",于是决策落在 tranche 层面而不是分子层面,动作空间从 10^10 降到 10^7 且可解释。
- **把最大的 ready-to-dock 库做成公共资产**:69 billion 分子、四种 3D docking 格式 + SMILES/SELFIES/Parquet,经 AWS Open Data 的 S3 bucket 直接云端访问、无需本地存储(原始 SMILES 以 CC-BY 署名 Enamine);SELFIES 版本直接服务生成模型,Parquet 版本直接服务大规模分析。
- **把 sampling algorithm × scoring function 解耦成可组合的 protocol 空间**:约 40 个程序组合出约 1,500 个 protocol,单一 CLI/配置文件即可切换,覆盖 protein/RNA/DNA/peptide/covalent 与 ML docking(DiffDock、TANKBind、EquiBind)及 MD 重打分(MM/PBSA、MM/GBSA、BPMD),大幅降低非专家与 ML 社区的使用门槛。
- **把 ML 当一等公民而非附件**:AFU 的 API mode 让 docking score 可直接作为生成/优化模型的目标函数;prescreen 自动产出带标签数据(Parquet + Athena 查询),主动学习层可重复任意轮数,形成"筛选即数据生成"的闭环——作者明确说平台不仅用于**应用** ML,也用于**开发** structure-based drug discovery 的 ML 架构与流水线。
- **把云原生工程细节当作方法的一部分来量化**:collection/subjob/work unit 三层并行、约 30 分钟的 subjob + 自动重跑 + spot-capacity-aware 调度,使 5.6 million spot vCPU 的运行损失 <0.1%;Slurm 提交模板把工作流逻辑与集群配置解耦;ARM 支持与编译器级优化(QuickVina 2 快 18%)也都给了数字。
- **端到端的前瞻性验证,并顺带产出机制生物学**:两个机制上不同的靶点(氧化还原酶 FSP1、DNA 修复酶 PARP1)都从纯虚拟筛选一路走到纳摩尔抑制剂 + 共晶结构 + 细胞内靶点结合,还给出 FSP1 催化机制(NAD(P)H 与 coenzyme Q 同时结合、兼有 oxidase 活性)的结构解释,以及"选择性抑制 quinone 还原可能反转 FSP1 表型"的新药理假设。

## 局限
- **化学空间聚焦的有效性是靶点依赖的**,作者自己明说("the effectiveness of chemical space focusing is target dependent");收益最大的是口袋复杂、特征丰富的蛋白,而对浅而无特征的位点能省多少、会不会失效,论文没有给出失败案例分析。
- **基准的评价指标是 docking score,不是实验亲和力**。三臂之间 top-50 平均 docking score 的差距多在 0.1–0.4 kcal mol⁻¹,远小于打分函数本身的误差;而"穷举最优"这条参考线只存在于 5-million 子集上,69-billion 全库没有(也不可能有)穷举基线——因此"最多省 1,000 倍"是相对一个**从未被实际运行过**的基线说的。与一个调好的传统漏斗式筛选相比到底省多少,正文没有正面回答。
- **主动学习层在真正的生产规模运行中没被用**:production-scale benchmark 明确"不加 active learning 以减少计算开销",FSP1 的 primary screen 也标注 "without ML feature"。ML 增强的证据因此全部来自 5-million 子集,其在 69-billion 规模上的增益是**推断**("we expect that incorporating active learning could yield further improvements")而非实测;论文摘要强调的 "optional active learning" 与两个湿实验成功案例之间并无因果链。
- **分类器学的是打分函数,不是活性**:标签直接取 prescreen docking score 的最负 25%,因此这一层学到的是"复现 QuickVina 2 的偏好",打分函数的系统误差会被继承;第 75 百分位这个决策边界与 0.5 的概率阈值都是固定启发式,没有做敏感性分析。
- **tranche 决策的粒度假设未被检验**:18 维的分箱方案、"每维取最好 bin 再做笛卡尔积"的超矩形启发式、以及 ligand efficiency 的使用,都没有与别的子空间选择方法(基于 scaffold、基于相似性检索、或基于学习的 surrogate)做对照;prescreen 每个 tranche 只用 1–10 个代表,而 tranche 平均含 5,600 个分子、占据度跨多个数量级(有 >10 million 分子的 tranche),单个代表能代表多大的方差没有量化。
- **命中率的分母被人工筛选过**:FSP1 是 10 million 分子对接 → 42 个订购(37 cluster、SwissADME 零警示 + 多条性质与毒性过滤)→ 33 个合成 → 2 个一级命中;PARP1 是 160 个合成 → 7 个抑制剂 → 4 个 <250 nM。这些比例混入了专家的过滤与挑选,不能直接读作"虚拟筛选的命中率",也无法把 AdaptiveFlow 的贡献与"大库本身更容易出好分子"分开。
- **从命中到可用化合物仍有明显缺口**:iParp1 酶学 IC50 8.8 nM 与 olaparib 相当,但细胞活性弱,被归因于水解造成的膜通透性差;FSP1 的结构工作用的是序列同一性 72.5% 的祖先蛋白而非人蛋白(细胞内结合另由 CETSA 证实);细胞 ADME 的结论只是 afi-FSP-3"最适合继续优化",也就是说还没有一个成药分子。另外 REAL Space 是按需合成库,82% 的合成成功率意味着订购的候选有一部分拿不到实物(本文即 42 个订购 → 33 个合成)。
- **资产本身的门槛与利益关系**:ready-to-dock 库压缩后约 200 TB(未压缩约 2 PB),实际使用几乎必须走 AWS S3;库是单一供应商(Enamine)的 2022 年版本,而正文自己指出 on-demand 空间已到万亿级;重现 5.6 million vCPU 级别的运行需要云额度(作者致谢 AWS 研究额度与 ChemAxon 的免费学术许可);多位作者分别任职或创办 Enamine、Onepot AI、AWS、Google、NVIDIA、Intel 与计算药物发现服务公司(Virtual Discovery、Phind Beteiligungs UG)。此外 "near-linear scaling" 的直接证据来自 AFLP,AFVS 只是"预期相同"。

## 与本研究方向的关系
这篇是 Sikander Hayat lab(Uniklinik Aachen)课题 **"Autonomous scientific orchestration of virtual screening"**(thesis/HiWi:LLM agent + molecular foundation model + docking + active learning,给定蛋白结构自主规划、执行、改进筛选 campaign 并找出合适化合物,应用方向为心脏疾病)的 **key paper 1**,在四篇阅读材料里扮演的角色是"**agent 要调度的那台机器**"。关键在于:论文已经把一个 ULVS campaign 拆成了参数化、可配置、可脚本化的阶段,而作者明确把 AFU 的 API mode 设计给"开发药物发现新方法的 ML 社区"使用——agent 需要的 handle 基本都已存在,不必自己造筛选引擎。

**可以直接包成 agent tool 的部分(都对应论文中实际存在的接口)**:(1) `prepare` = AFLP —— 受体/配体准备 + 28 个性质计算,输入可为 SMILES、SELFIES 或氨基酸序列,每一步可选工具;(2) `tranche_select` —— 在 18 维矩阵上手动选 tranche 或用 hyperrectangle 法选超矩形(交互式 web interface 的 18 个滑块语义,正是 agent 要输出的那组约束);(3) `prescreen` = ATG prescreen —— 代表分子数(1–10)× exhaustiveness,输出 Parquet;(4) `query` —— 用 Amazon Athena 对 prescreen 结果做 SQL 查询(天然的 agent 工具形态,也是"选格"决策的证据来源);(5) `primary_screen` —— 用户指定分子预算的全量对接;(6) `ml_filter` —— 一个配置参数开关的 Morgan-fingerprint 分类器(课题里 "active learning" 的现成底座,也是把 DrugCLIP 式对比学习打分器替换进来的插槽);(7) `rescore` —— 第三阶段高精度重打分(受体柔性、MM/PBSA、MM/GBSA、BPMD);(8) `pose_check` —— PoseBusters 的物理合理性检查,可作为 agent 的自动 sanity check;(9) `dock(protocol=…)` —— 约 1,500 个 protocol 的单接口选择;(10) `submit` —— 填充 Slurm / AWS Batch 提交模板(job array、partition、memory)并设定 subjob 时长与 spot 策略,即 agent 的"算力与预算"动作。

**agent 实际可以做的决策(每条都有论文中的量化依据)**:**选哪个 docking protocol** —— 约 1,500 个组合是一个真实的离散动作空间,而论文证明 binning 对 protocol 不敏感(QuickVina 2 / Smina-Vinardo / GWOVina 的 speedup 与 enrichment 可比),所以 agent 可以安全地"便宜 protocol 做 prescreen、贵 protocol 做 rescoring",并按靶点类型(kinase / GPCR / PPI interface / RNA / 共价)挑程序;Extended Data Fig. 9 的单次计算耗时就是它做成本估算的查找表。**选哪块化学子空间** —— 18 维性质约束是 agent 最自然的输出形式,而论文自己示范了把靶点与下游需求翻译成约束的全过程(FSP1 用了 logP < 5、logS > −5、TPSA < 140 Å²、立体中心 ≤ 3,加 SwissADME 零警示与跨 37 个 cluster 的分散采样);心脏方向所需的约束可以挂在同一套维度上。**花多少算力** —— prescreen 规模(12 million 全库 vs 加动态过滤)、代表分子数(1 vs 10)、exhaustiveness(1 vs 10)、primary screen 预算(论文实际用过 10,000 / 100,000 / 1 million / 10 million / 100 million)全是显式旋钮。**什么时候停** —— 论文给了四类停机信号的雏形:prescreen 超参的收益已饱和(三种设置结果相近 ⇒ agent 不该在这里加钱)、top-50 平均 docking score 与"穷举最优"参考线的剩余 gap(5M 子集上 100K ATG+AL 仍差约 0.5–1.6 kcal mol⁻¹)、ML 过滤掉的比例(30–70%)、以及"再加一轮是否还能改进"——FSP1 的第二轮(用 FSP1–afi-FSP1-1 共晶结构重筛、20 个类似物 → 4 个新抑制剂)正是 agent 应该学会自己触发的 SAR 迭代。**选哪些分子去买/合成** —— cluster 分散 + 性质过滤 + 毒性/ADME 警示过滤,是一个完全可自动化但本文仍由专家执行的决策点,也是 agent 最容易展示增量价值的位置。

**一个合理的第一个 thesis milestone**:在 5-million 化合物的 test-based benchmark 设置下复现并包装论文的三臂实验(配方齐全:从 Enamine 空间随机抽合成反应构库、QuickVina 2 默认参数、1M random / 100K ATG / 100K ATG+AL 三臂、top-50 平均 docking score 为指标、全库穷举值作参考上界、10 个跨类别靶点),把它做成一个 agent 可调用的 harness;然后让 LLM agent 在**只给定受体结构与一句自然语言目标**的条件下自己产出 AFU/AFVS 配置文件(选 protocol、写 18 维约束、定 prescreen 与 primary screen 预算、决定是否开 ML 过滤、决定是否再来一轮),与论文手工设定的 100K ATG+AL 对照两个问题:**相同 docking 预算下 agent 的配置能否打平或更好**,以及**agent 能否在收益饱和处自己停下**。选这个 milestone 的理由:指标、基线、参考上界、复现所需的代码与数据全部开放(GPL-2.0 代码 + AWS Open Data 的库 + 10 个基准靶点),规模小到单机或小集群可跑(不需要 5.6 million vCPU),产物(agent trace + 配置 schema)直接可用于下一步换心脏靶点、接 DrugCLIP 打分器或接 co-folding 重打分。

**与另外三篇读物的分工**:EXSCALATE 是同一问题的"**穷举 + HPC**"解(1 trillion 次评估),AdaptiveFlow 是"**自适应 + 云**"解,两者正好给 agent 的 compute-allocation 策略划出两个极端(买算力 vs 买信息);DrugCLIP 的对比学习打分器可以替换或前置于 ATG prescreen 里的 docking —— prescreen 那 12 million 次 docking 是整条流程里最大的固定成本,也是最值得被 foundation model 近似的一步;pairwise competitive docking(AF3/Boltz co-folding)则正好落在 AdaptiveFlow 第三阶段"更高精度重打分"的插槽里,并提供 docking score 之外的排序信号(这对缓解本文"ML 层只是在学打分函数"这一局限尤其重要)。**必须注意**:本文没有任何心脏相关靶点(靶点是 FSP1、PARP1 与 10 个基准蛋白,背景以肿瘤为主),所以心脏方向只能借其**流程与基础设施**,靶点、通路与 ADME 约束必须自己定义;FSP1 是 ferroptosis / 脂质过氧化的调控者、本文也提到其在癌症抗性中的角色,但**论文完全没有涉及心脏**,不应据此推断相关性。
