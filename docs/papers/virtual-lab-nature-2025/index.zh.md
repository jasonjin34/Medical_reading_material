# The Virtual Lab of AI agents designs new SARS-CoV-2 nanobodies

> **文献键** `Swanson_2025` · **来源** Nature(2025) · **类别** agents · **相关度** medium · **获取** paywall
> **链接** <https://doi.org/10.1038/s41586-025-09442-9> · `status: complete`

---

## 一句话
Stanford(Zou 组)与 CZ Biohub 的 Virtual Lab:一个 LLM「PI agent」带领若干由它自己定义的 LLM 科学家 agent(免疫学家、机器学习专家、计算生物学家)外加一个 Scientific Critic,通过「团队会议 + 单独会议」推进一个真实的跨学科课题,人类只提供高层议程与反馈;在一个蛋白结合体设计任务上,agent 团队自主选择并串联了三种已有公开工具(ESM、AlphaFold-Multimer、Rosetta)形成计算流程,产出的候选分子经人类实验室表征,多数可表达且保留原有特异性,其中两个显示出对较新变异株的结合改善。全过程人类只写了全部文字的 1.3%。

## 研究问题
跨学科研究需要越来越大的团队(AlphaFold 2 论文 34 位作者),而多数科学家、尤其资源有限的组,接触不到多领域专家。LLM 擅长回答单个科学问题,但开放式、多步、跨领域、充满未知的研究与之不同。已有系统要么局限于单一领域(ChemCrow、Coscientist 的化学任务),要么只在机器学习子领域内且无真实实验(AI Scientist),要么只生成想法不实现(Si et al.)。问题是:能否让一组 LLM agent 在少量人类指导下完成一个**真实的跨学科课题,并得到实验验证的结果**?

## 方法
**Agent 定义**:每个 agent 由四要素提示定义——title、expertise、goal、role。人类定义 PI 与 Scientific Critic;PI 再按项目简介、以自己的提示为范例自动创建科学家 agent。底座模型为 GPT-4o。**会议机制**:输入包括议程(必需)、议程问题与议程规则(可选)、往次会议摘要、额外上下文(如论文)、轮数(通常 N = 3)。**团队会议**:PI 开场给出初步想法与引导问题 → 每位科学家 agent 依次就已有讨论发言 → Scientific Critic 批评 → PI 汇总、做决定并追问;N 轮后 PI 写摘要、给建议并回答议程问题——人类只需读这份最终回复。**单独会议**:单个 agent 完成具体任务(如写代码),每轮由 Critic 给出改进意见,最后一轮输出改进版答案。**并行会议**:同一会议以较高「创造性」温度 0.8 并行跑 5 次,再以较低「一致性」温度 0.2 开一次合并会议,综合各次最优部分(比多数投票更灵活)。**项目流程(五个阶段)**:组队(PI 选出三位科学家 agent)→ 项目规格(团队会议回答「做什么、改造已有分子还是从头设计、以哪些已知分子为起点」等议程问题)→ 工具选择(团队会议列出可用的公开模型/软件)→ 工具实现(各 agent 在 Critic 协助下写脚本,再用一次跟进会议修掉初版错误)→ 工作流设计(PI 决定三种工具如何组合、用加权打分筛选候选并迭代多轮)。随后由人类实验室对入选候选做表征。

## 数据
不涉及训练数据集;所用资源为三个已公开的计算工具(蛋白语言模型 ESM、结构预测 AlphaFold-Multimer via LocalColabFold 1.5.5、计算生物学软件 Rosetta REF15)与公开的已知分子/结构(PDB 条目)。评估层面的「数据」是会议记录与字数统计:人类 1,596 词 vs agent 122,462 词。实验表征在人类实验室完成(大肠杆菌表达 + 抗原阵列 + 多重 ELISA),候选规模为 92 个设计 + 4 个未突变参照。

## 主要结果
- **人类投入极小**:全流程人类写 1,596 词(含从打分文件复制的文本),占全部文字的 **1.3%**;agent 写 122,462 词(98.7%),包括全部从零写出的 Python 脚本与一个 XML 脚本。
- **agent 自主做出的高层决策**是可审计的,并附理由:选择改造已有分子而非从头设计(可利用已有结构数据与已知效力,更快更可靠),并给出 4 个起点分子;以及把工作重点放在特定结合域上。
- **自主搭建的计算流程可用**:agent 写的三段脚本(ESM 打分约 130 行、结构界面置信度计算约 144 行、Rosetta 结合能提取约 71 行 + 30 行 XML)在人类指出初版错误后可运行;PI 设计的加权打分**正确地给结合能项用了负权重**(更负更好),显示它理解各指标方向。
- **实验表征**:92 个设计中 38%(35/92)表达量高到很高,只有 6.5%(6/92)几乎无可溶表达,说明引入的改动总体被良好耐受、未造成大规模错误折叠或聚集;多数设计保留了对原始抗原的特异性(其中两个系列 96%、44/46 保留)。
- **两个候选显示新增结合**:两个设计在保持对原始抗原结合的同时获得了对较新变异株的中等结合,并经剂量稀释曲线确认(EC50 弱于对原始抗原);作者对可能的机理给出基于电荷互补的推测,并指出某些位点的改动不被耐受(一个系列整体对原始抗原结合变差),以及一处无意引入的半胱氨酸导致 3 个设计出现高非特异结合。
- **保留原特异性的归因**:作者认为普遍保留甚至改善对原抗原的结合,主要来自 ESM 似然这种**与抗原无关、只偏好进化上合理序列**的打分,而新增的变异株结合更可能来自结构/能量项。

## 创新点
- 把「实验室」本身作为 agent 架构:PI + 自动生成的专业 agent + 显式 Critic,通过结构化会议(团队/单独 × 并行 + 合并)组织跨学科讨论,人类只在议程层面介入。
- **并行会议 + 温度分工**(高温生成多样答案、低温合并)是一个简洁而通用的质量提升机制。
- 显式 Critic agent 的作用被具体展示(它写的字数甚至多于各科学家 agent,因为要点评所有人)。
- 在一个开放式课题上做到「agent 决策 → agent 写工具 → 人类实验验证」的端到端闭环,并量化人机文字贡献比。

## 局限
- **知识截止**:agent 不知道最新文献与软件版本,因此没提出当时更新的工具(用 AlphaFold-Multimer 而非 AlphaFold 3),并写出假定旧函数名、与新版包不兼容的代码——需人类指出后修正(作者建议用 RAG 缓解)。
- **工具本身不完美**:即使正确调用,结构预测等工具的误差仍限制结果可靠性。
- **需要提示工程**:缺乏明确引导时 agent 答案含糊、回避硬性决策(被要求二选一时常说「两个都做」,直到明确写「只选一个」);人类可能要反复迭代议程。
- 只在一个课题上验证;实验为体外结合表征,新增结合为中等强度、EC50 弱于原抗原,距离可用候选还远;单一底座模型(GPT-4o),无跨模型比较。

## 与本研究方向的关系
Virtual Lab 与我们方向的关系主要在**架构与评估**层面,而非生物学内容。它展示了一个「只给议程、让 agent 团队自己决定技术路线并写出工具」的工作模式——对应 detect → model → revert 中的 **model/revert 流程设计环节**:例如给定「在虚拟组织中预测哪些扰动能把异常程序拉回正常」这个议程,让一个 agent 团队自己决定用哪些模型(扰动预测、空间整合、通路富集)、如何组合与打分。三点具体启示:**(1) 可审计的决策记录**——它的团队会议把每个高层决策与理由都写下来,这种「议程问题 → 答案 → 理由」结构正是 Plan B 想要的 claim-to-evidence 骨架的上游形态(决策层而非结论层);**(2) 显式 Critic 与并行+合并**——对应 Plan B 的「校准 verifier」与「重跑稳定性」:高温并行产生多样答案、低温合并,本质上是用集成换稳定性,与 Robin 的 8 轨迹共识是同一思路的两个实现,可以一起作为稳定性机制的对照;**(3) 知识截止导致的工具选择过时**——这是组学 agent 的高频失败模式(用过时的 pipeline、旧版函数、已被取代的方法),应作为「组学特定失败分类」中单列的一类:在 snRNA/snATAC/Xenium 领域,工具与最佳实践每年都在变(ambient RNA 校正、分割、doublet 检测),agent 选错方法往往不会报错、只会静默产生不可靠结论。另外值得注意的是,它的主要积极结果(保留原特异性)被作者归因于一个**与目标无关的先验打分**(序列进化合理性),而真正指向目标的结构/能量项贡献较弱——这对我们是一个方法学警示:在虚拟组织扰动打分里混入「与目标无关但能保证合理性」的先验项,可能让结果看起来成功,但未必是因为模型理解了目标。
