# CLAUDE.md

Guidance for Claude Code (and any AI agent) working in this repository.

## What this repo is

A **living, standardized literature base** for one research direction:

> **Anomaly-detection-based virtual tissue modelling** — detect regions of
> biomedical images / spatial-omics changed by disease or drug perturbation
> (**anomaly detection**) → model tissue as a manipulable **virtual tissue** →
> predict the key genes / perturbations that **revert** the anomaly (validated
> in the wet lab). Think of it as a three-stage pipeline: **detect → model → revert**.

It is a *pipeline*, not just a folder of notes: metadata, BibTeX, the relationship
graph, and the website all regenerate from per-paper source files.

## Layout

```
papers/<slug>/           one folder per item (paper | dataset | model | code | competition)
  metadata.yaml          canonical record — SOURCE OF TRUTH for title/venue/doi/relevance/…
  deep-read.md           论文精读 — bilingual (中 + EN) close reading
  ai-ready.md            clean full-text/abstract extract, meant to be pasted into an LLM
  citation.bib           per-paper BibTeX fragment
  s2.json                cached Semantic Scholar references (for the graph); optional
references.bib           GENERATED — all bib entries (do not hand-edit)
literature-review.md     hand-written synthesis across all papers
relationships/
  _narrative.md          hand-written narrative (prepended into relationships.md)
  relationships.md        GENERATED — narrative + Mermaid graph + edge tables
  graph.json / graph.mmd  GENERATED
docs/                    GENERATED MkDocs site source (do not hand-edit)
mkdocs.yml               GENERATED by build_site.py (do not hand-edit)
templates/               canonical shapes for new papers
scripts/                 the pipeline (see below)
```

## The one workflow — adding / updating a paper

```bash
pip install -r requirements.txt          # once
python scripts/add_paper.py <url|doi|arxiv> --category <c> --relevance <high|medium|low> [--access <open|paywall|abstract-only>]
# → creates papers/<slug>/ from templates + auto-fetched metadata + citation.bib
# then edit papers/<slug>/deep-read.md (fill the bilingual sections)
python scripts/build_bib.py              # regenerate references.bib
python scripts/build_relationships.py    # regenerate the graph (queries Semantic Scholar)
python scripts/build_site.py             # regenerate docs/ + mkdocs.yml nav
git add -A && git commit -m "add <slug>: <title>" && git push
```

`--category` ∈ `single-cell · spatial · virtual-tissue · histopath · foundation · pathology · imaging · competition · other`.

Pushing to `main` triggers `.github/workflows/pages.yml`, which runs
`mkdocs build --strict` and deploys to **https://jasonjin34.github.io/Medical_reading_material/**.

## Rules for editing

- **Generated files are off-limits to hand-edits.** Never edit `references.bib`,
  `relationships/relationships.md`, `relationships/graph.*`, `docs/**`, or
  `mkdocs.yml`. Edit the *sources* (`citation.bib`, `_narrative.md`, `metadata.yaml`,
  `templates/`, `literature-review.md`) and re-run the build scripts. The build
  scripts are idempotent.
- **Deep-reads are bilingual** (Chinese first, then English) with these sections:
  一句话/One-liner · 研究问题/Problem · 方法/Method · 数据/Data · 主要结果/Key results ·
  创新点/Contributions · 局限/Limitations · **与本研究方向的关系/Relation to our
  direction** · 可复用资产/Reusable assets · 待读/Follow-ups. English technical terms
  may stay in English inside Chinese sentences.
- **Never fabricate.** For paywalled items, base notes on the abstract + public
  landing content + any legitimate open preprint, and mark `status: abstract-only`.
  When the user later drops a `source.pdf` into a paper folder, enrich from it.
- **Conceptual relationships are curated by hand** in `scripts/build_relationships.py`
  (`CONCEPT_EDGES`) because these papers are parallel 2025–26 works that mostly do
  not cite each other. Add an edge there when a new paper shares a method/dataset/
  backbone with an existing one.
- Keep the `id`/folder name (`slug`) and `bibkey` stable once a paper is cited.

## Commit & verify conventions

- Verify before committing non-trivial changes: `mkdocs build --strict` must pass.
- Commit/push only when the user asks (they usually do for this repo).
- Local preview: `mkdocs serve`.

## Environment notes

- Scripts use only the Python **standard library** for HTTP (so they run before
  `pip install`). Metadata sources: DOI content-negotiation / Crossref transform,
  the arXiv API, GitHub & Hugging Face APIs, and Semantic Scholar (unauthenticated;
  a ~1s delay between calls avoids throttling).
- `site/`, `.venv/`, `__pycache__/`, `.DS_Store` are git-ignored.
