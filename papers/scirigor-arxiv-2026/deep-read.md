## 一句话 / One-liner
<!-- ZH --> SciRigor 把科研分析 agent 的产出(代码、结构化结果、图、原子论断)重建为一张**类型化证据图**,要求每条主要论断都有一条在同一次运行中可验证的「数据→变换→结果→图/论断」完整支撑路径,并按 weakest-link 打分、定位最早断裂的边;在 100 个来自 Nature 等期刊的图级案例上,agent 的论断与自身结果一致率几乎与结果是否正确无关(91.8% vs 91.0%),最好的系统 strict 全链成功率仅 18.0%。
<!-- EN --> SciRigor reconstructs a scientific-analysis agent's outputs (code, structured results, a figure, atomic claims) as a **typed evidence graph**, requires every primary claim to keep a complete, same-run verifiable "data → transform → result → visual/claim" support path, scores it by weakest link and localises the earliest broken edge. On 100 figure-level cases from Nature and other journals, agents' claims agree with their own results at nearly the same rate whether those results are right or wrong (91.8% vs 91.0%), and the best system achieves only 18.0% strict whole-chain success.

## 研究问题 / Problem
<!-- ZH --> 科研编码 agent 正在执行长程开放式分析,产出彼此依赖的代码、数值、图和结论。现有基准要么评代码/执行,要么评整条工作流是否交付,要么孤立地评图或论断 —— 都没有回答:**一条新生成的论断,是否真的被同一次运行中的数据、计算和可视化所支撑?** 典型失败:回归在 log 尺度上存估计值和置信区间,agent 只变换了点估计,写出「增加 18.0%(95% CI 12.6–23.6%)」这样看似正确的句子,而它自己的区间与图仍在错误尺度上。只看最终输出会接受这种「对的句子、错的证据」,而精确参考匹配又会拒绝合理的替代分析。
<!-- EN --> Scientific coding agents now run long-horizon open-ended analyses producing interdependent code, numbers, figures and conclusions. Existing benchmarks score code/execution, workflow delivery, or figures/claims in isolation — none asks: **is a newly generated claim actually supported by the data, computation and visualisation produced in the same run?** Typical failure: a regression stores an estimate and CI on a log scale; the agent back-transforms only the estimate and writes a correct-looking "18.0% increase (95% CI 12.6–23.6%)" while its structured interval and plotted band stay on the wrong scale. Final-output scoring accepts such "right sentence, wrong evidence", while exact-reference matching rejects defensible alternative analyses.

## 方法 / Method
<!-- ZH --> **任务**:给定科学问题、分析就绪数据与研究背景,agent 必须产出四类相互依赖的产物 —— 可执行分析代码、结构化数值结果、数据绑定的可视化、原子科学论断;重跑代码必须能再生结果、图和论断并暴露 provenance。成功 = 覆盖所需发现 + 每条主要论断至少有一条已验证的计算与视觉支撑路径。**证据图评测**:构建期,策展人执行冻结的作者工作流,把数据视图、变换、统计结果、视觉标记与原子发现规范化为语义槽,每个论断槽链接 ≥1 个计算支撑集和 ≥1 个视觉支撑集(集内联合必需,不同集代表被认可的替代方法/编码),并经人工审计。评测期,评估器从运行时 trace、再生结果与独立数值 oracle、捕获的绘图对象和数组、结构化论断记录中**重建**候选证据图(agent 不提交图),节点(artifact fidelity:transform / result / visual / claim)与边(edge validity:数据→变换→结果、结果↔图、结果/图→论断)分开打分。谱系、数值重算、视觉绑定和图连通性程序化检查;冻结的语义匹配器只处理论断复述与范围匹配,且不能推翻失败的结构/数值/provenance 检查。**打分**:路径内取最小(weakest-link),路径间取最大(接受任一完整的已批准替代路径);输出 evidence-chain precision/recall/F1、执行门控的 SoftECS,以及 Strict(执行成功 + 所有必需论断全支撑 + 无无支撑主论断 + 满足全部硬视觉约束)。不完整的链报告最早断裂层级:contract/execution、Data→Transform、Transform→Result、Transform/Result→Visual、Result/Visual→Claim。
<!-- EN --> **Task**: given a question, analysis-ready data and study context, the agent must produce four interdependent artefacts — executable analysis code, structured numerical results, a data-grounded visualisation and atomic claims; re-running the code must regenerate results, figure and claims and expose provenance. Success = required findings covered + every primary claim has at least one verified computational and visual support path. **Evidence-graph evaluation**: at construction, curators execute the frozen author workflow and canonicalise data views, transforms, statistical results, visual marks and atomic findings into semantic slots; each claim slot links to ≥1 computational and ≥1 visual support set (items within a set jointly required; separate sets are approved alternative methods/encodings), human-audited. At evaluation, the evaluator **reconstructs** the candidate graph from runtime traces, regenerated results with independent numerical oracles, captured plotting objects/arrays and structured claim records (the agent does not submit the graph); nodes (artifact fidelity: transform / result / visual / claim) and edges (data→transform→result, result↔visual, result/visual→claim) are scored separately. Lineage, numerical recomputation, visual binding and connectivity are checked programmatically; a frozen semantic matcher handles only paraphrase/scope matching and cannot override a failed structural, numerical or provenance check. **Scoring**: minimum within a path (weakest link), maximum across approved complete paths; reports evidence-chain precision/recall/F1, an execution-gated SoftECS, and Strict (execution + complete support for every required claim + no unsupported primary claim + all hard visual constraints). Incomplete chains report the earliest broken layer: contract/execution, Data→Transform, Transform→Result, Transform/Result→Visual, Result/Visual→Claim.

## 数据 / Data
<!-- ZH --> 100 个证据完整的图级案例,来自 27 篇实证文章(Nature、Science 主刊经 Europe PMC 检索,以及 Nature Portfolio 等开放获取来源),覆盖 6 个领域、17 个子领域:经济与政策 24、计算与信息科学 23、社会与行为科学 22、认知科学 15、**生命与健康科学 9**、物理科学 7。准入要求:作者生成的定量图 + 对应 Results 段落 + 作者公开的完整绘图脚本/notebook + 所有被消费的数据文件;两次干净复现并与论文图一致;非 Python 工作流移植为 Python(GPT-5.6 辅助、策展人逐项核对)。评测 11 个 agent/模型配置(GPT-5.5 / GPT-5.6 / GPT-5.6-Sol 不同推理档、Claude Sonnet 5、Kimi-K3、Qwen3.8-Max、Qwen3-Coder-30B-A3B、Qwen-AgentWorld-35B-A3B)。
<!-- EN --> 100 evidence-complete figure-level cases from 27 empirical articles (Nature and Science main journals via Europe PMC, plus Nature Portfolio and other open-access sources), spanning 6 domains and 17 subfields: economics & policy 24, computing & information sciences 23, social & behavioural 22, cognitive science 15, **life & health sciences 9**, physical sciences 7. Admission requires an author-generated quantitative figure + its Results passage + complete author-released plotting script/notebook + every consumed data file; two clean reproductions agreeing with the paper figure; non-Python workflows ported to Python (GPT-5.6-assisted, curator-verified). Eleven agent/model configurations evaluated (GPT-5.5 / GPT-5.6 / GPT-5.6-Sol at several reasoning levels, Claude Sonnet 5, Kimi-K3, Qwen3.8-Max, Qwen3-Coder-30B-A3B, Qwen-AgentWorld-35B-A3B).

## 主要结果 / Key results
<!-- ZH -->
- **最好也只有 18.0% strict**:GPT-5.5(xhigh)执行 100%、SoftECS 62.6%、Strict 18.0%;GPT-5.5(high)16.0%;GPT-5.6-Sol(high)13.0%;其余 ≤11%,Claude Sonnet 5、GPT-5.6(low)及两个 Qwen 小模型为 0。
- **执行本身是瓶颈**:Kimi-K3 执行 79.0%、Qwen3.8-Max 47.0%、Qwen3-Coder-30B-A3B 29.0%、Qwen-AgentWorld-35B-A3B 12.0%;Kimi-K3 从 79.0% 执行跌到 SoftECS 35.0%、Strict 1.0%。
- **自洽掩盖错误**:Result→Claim 一致性在 11 行中总是最高或次高;如 GPT-5.6(low)Result→Claim 97.9%,但 result fidelity 仅 47.2%、claim fidelity 52.5%。
- **自洽与正确几乎无关**:Result→Claim 一致性在结果正确的轨迹上通过 91.8%,在结果错误的轨迹上仍通过 91.0%;Result→Visual 稍敏感,但错误结果下仍通过 82.2%(正确时 97.3%)。
- **断在上游**:936 条未达 strict 的轨迹中,48.2% 最早断在数据选择/变换,30.1% 断在契约/执行门,11.9% 在结果计算,可视化+论断+provenance 合计仅 9.8%(合计 78.3% 断在执行或数据/变换层)。在 718 条成功执行的轨迹中,transform fidelity 失败 59.6%、result fidelity 49.3%、claim fidelity 47.9%,而 Result→Claim 一致性只失败 8.6%。
- **复杂度效应**:GPT-5.6-Sol(xhigh)从 1 个输入资产到 ≥5 个,Strict 从 45.7% 降到 25.0%、F1 从 70.9% 降到 57.8%,而只看论断的分数从 71.7% 仅降到 63.7% —— 复杂度主要伤害链完整性而非论断表面合理性。
<!-- EN -->
- **Best is only 18.0% strict**: GPT-5.5 (xhigh) executes 100%, SoftECS 62.6%, Strict 18.0%; GPT-5.5 (high) 16.0%; GPT-5.6-Sol (high) 13.0%; others ≤11%, with Claude Sonnet 5, GPT-5.6 (low) and two small Qwen models at 0.
- **Execution is itself a bottleneck**: Kimi-K3 executes 79.0%, Qwen3.8-Max 47.0%, Qwen3-Coder-30B-A3B 29.0%, Qwen-AgentWorld-35B-A3B 12.0%; Kimi-K3 falls from 79.0% execution to 35.0% SoftECS and 1.0% Strict.
- **Self-consistency masks error**: Result→Claim consistency is the highest or second-highest score in all 11 rows; e.g. GPT-5.6 (low) has 97.9% Result→Claim consistency but only 47.2% result fidelity and 52.5% claim fidelity.
- **Consistency is nearly independent of correctness**: Result→Claim consistency passes on 91.8% of result-faithful and 91.0% of result-unfaithful trajectories; Result→Visual is more sensitive but still passes 82.2% with unfaithful results (97.3% faithful).
- **Chains break upstream**: of 936 non-strict trajectories, 48.2% first fail at data selection/transformation, 30.1% at the contract/execution gate, 11.9% at result computation, and only 9.8% at visualisation + claims + provenance (78.3% at execution or data/transform). Among 718 executed trajectories, transform fidelity fails 59.6%, result fidelity 49.3%, claim fidelity 47.9%, while Result→Claim consistency fails only 8.6%.
- **Complexity**: for GPT-5.6-Sol (xhigh), going from 1 to ≥5 input assets lowers Strict from 45.7% to 25.0% and F1 from 70.9% to 57.8%, while a claims-only score drops only from 71.7% to 63.7% — complexity hurts chain completeness, not surface claim plausibility.

## 创新点 / Contributions
- <!-- ZH --> **评分对象 = 已验证的数据→论断支撑路径**,而非程序、阶段或最终输出。 <!-- EN --> **The scored object is a verified data-to-claim support path**, not a program, stage or final output.
- <!-- ZH --> **节点保真与边有效性分离**:区分「产物本身错」与「产物之间的依赖不成立」。 <!-- EN --> **Separates artifact fidelity from edge validity**: distinguishes "the artefact is wrong" from "the dependency between artefacts does not hold".
- <!-- ZH --> **weakest-link + 替代路径**:上游错误不能被下游的漂亮呈现修复,同时接受科学上等价的方法与可视化编码。 <!-- EN --> **Weakest-link + alternative paths**: downstream polish cannot repair an upstream error, while scientifically equivalent methods and visual encodings are admitted.
- <!-- ZH --> **定位最早断裂边**,把失败归因到具体证据层。 <!-- EN --> **Localises the earliest broken edge**, attributing failure to a specific evidence layer.
- <!-- ZH --> 用作者公开代码+数据的图级复现构造「证据完整」案例,每例两次干净复现 + 人工审计。 <!-- EN --> Builds "evidence-complete" cases from figure-level reproductions with author code + data, each passing two clean reproductions and human audit.

## 局限 / Limitations
- <!-- ZH --> 只评可观察的产物,不看 agent 的推理或动作轨迹,因此无法判断失败源于规划、实现还是无根据生成。 <!-- EN --> Scores observable artefacts only — not reasoning or action trajectories — so it cannot tell whether a failure stems from planning, implementation or unsupported generation.
- <!-- ZH --> 案例分布由「是否有图级公开代码 + 完整数据」决定,不是文献的概率平衡样本;生命与健康科学只有 9 例,组学类分析占比很小。 <!-- EN --> Case distribution reflects availability of figure-level public code + complete data, not a balanced sample; life & health sciences contribute only 9 cases, with little omics-style analysis.
- <!-- ZH --> 冻结替代路径之外的方法需进入专家裁决,自动打分对真正新颖的分析仍可能过严。 <!-- EN --> Methods outside the frozen alternatives require expert adjudication; automated scoring may still be too strict for genuinely novel analyses.
- <!-- ZH --> 每个配置单次运行,未报告 rerun 方差;论文中未给出代码或数据链接。 <!-- EN --> One run per configuration, no rerun variance reported; no code or data link is given in the paper.

## 与本研究方向的关系 / Relation to our direction
<!-- ZH --> 这是 **课题 2 的「claim-to-evidence verification」在计算分析场景下最贴近的评测框架**,几乎可以作为课题 2 评测设计的模板。课题 2 要验证的正是「分析肾脏组学的 agent 说的话,是否被它自己跑出来的数据和计算所支撑」—— SciRigor 把这个问题形式化成证据图 + weakest-link + 最早断裂边。可直接迁移的点:**(1) 证据图的节点类型**(数据资产/变换/统计结果/视觉标记/论断)对应组学分析的 QC 过滤→归一化→聚类/注释→差异表达/空间统计→图→结论;**(2) 「自洽 ≠ 正确」的定量证据**(91.8% vs 91.0%)直接说明课题 2 的 verifier 不能只检查报告内部一致,必须做独立的数值重算(oracle);**(3) 失败集中在数据选择/变换层(48.2%)** —— 这与组学分析中最常见的错误位置(细胞过滤、批次校正、归一化、样本分组)高度吻合,可作为 omics-specific failure taxonomy 的上游大类;**(4) 「替代路径」机制** 解决了组学里「多种合理分析方案」的问题(不同归一化、不同聚类分辨率)。对 **课题 1**,它提醒 KidneyAnomalyBench 若让 agent 产出「异常区域 + 论断」,也应要求可重跑、可回溯的证据路径。缺口:SciRigor 没有组学/空间数据,生命健康类只有 9 例,且不评 rerun 稳定性 —— 这恰是课题 2(肾脏组学 + rerun stability)可以补的空白。
<!-- EN --> The closest evaluation framework to **Topic 2's claim-to-evidence verification** for computational analysis — nearly a template for Topic 2's evaluation design. Topic 2 asks precisely whether what a kidney-omics agent says is supported by the data and computation it actually produced; SciRigor formalises this as an evidence graph + weakest link + earliest broken edge. Directly transferable: **(1) evidence-graph node types** (data assets / transforms / statistical results / visual marks / claims) map onto omics steps: QC filtering → normalisation → clustering/annotation → DE / spatial statistics → figure → conclusion; **(2) quantitative evidence that self-consistency ≠ correctness** (91.8% vs 91.0%) means Topic 2's verifier cannot just check internal consistency of a report — it needs independent numerical recomputation (oracles); **(3) failures concentrate in data selection/transformation (48.2%)** — matching where omics analyses most often go wrong (cell filtering, batch correction, normalisation, sample grouping), a natural upstream class for the omics-specific failure taxonomy; **(4) the alternative-path mechanism** handles omics' "multiple defensible pipelines" (different normalisations, clustering resolutions). For **Topic 1**, if KidneyAnomalyBench asks agents for "anomalous regions + claims", it should likewise require re-runnable, traceable evidence paths. Gaps: SciRigor has no omics/spatial data, only 9 life-and-health cases, and no rerun-stability evaluation — exactly what Topic 2 (kidney omics + rerun stability) can supply.
