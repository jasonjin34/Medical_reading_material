## 一句话 / One-liner
<!-- ZH --> 这篇综述把「可检视的工作流轨迹」而非架构或最终答案作为分析单元,提出 Function–Evidence–Validation(FEV)框架:Function 记录 agent 实际演示了哪些工作流操作(F1–F6),Evidence 记录支撑动作与论断的可追溯来源(E1–E6),Validation 记录针对具体用例累积达到的保证等级(V0–V4 + 七个限定符);用它编码了 109 个生物信息 agent/近 agent 系统与 28 个基准 —— 规划与工具执行进展快,而可重放、溯源、外部验证与前瞻实验验证明显滞后(绝大多数停在 V3,仅 7 个到 V4)。
<!-- EN --> This review takes the inspectable workflow trajectory — not architecture or the final answer — as the unit of analysis and introduces the Function–Evidence–Validation (FEV) framework: Function records the workflow operations an agent demonstrably performs (F1–F6), Evidence the traceable sources supporting actions and claims (E1–E6), and Validation the cumulative assurance reached for a specific use case (V0–V4 plus seven qualifiers). Coding 109 bioinformatics agent/agent-adjacent systems and 28 benchmarks, it finds planning and tool execution advancing fast while replayability, provenance, external and prospective empirical validation lag (most systems at V3, only seven at V4).

## 研究问题 / Problem
<!-- ZH --> LLM agent 已在规划、执行和解释生物分析,但流畅的回答、成功的工具调用和 benchmark 成绩都不能证明科学可信:系统可能执行了不合适的分析、检索了权威但无关的证据、保留了可重放却支持不成立结论的计算,或者只实验验证了其主要论断的一小部分。已有综述按应用、架构、能力来组织生物 agent,也提到了证据、可复现、鲁棒性和验证,但**没有一个在单个被评估工作流层面同时操作化这些维度的共同框架**。作者主张从「最终答案正确」转向「工作流正确」。
<!-- EN --> LLM agents now plan, execute and interpret biological analyses, but fluent answers, successful tool calls and benchmark scores do not establish scientific credibility: a system may run an inappropriate analysis, retrieve authoritative but irrelevant evidence, preserve a replayable computation that supports an unjustified interpretation, or experimentally test only part of its principal claim. Prior reviews organise biological agents by application, architecture and capability and mention evidence, reproducibility, robustness and validation, but **no common framework operationalises them jointly at the level of an individual evaluated workflow**. The authors argue for moving from final-answer correctness to workflow correctness.

## 方法 / Method
<!-- ZH --> **定义**:区分 bioinformatics copilot(辅助用户主导的分析)、workflow engine(如 Nextflow/nf-core,执行预定义流水线,能把不合适的流水线正确地跑完)与 agentic bioinformatics layer(自适应控制工作流);完整的 agent 层需同时具备:目标导向的多步可修订规划、有状态的工具执行、可检视的科学支撑(证据、trace、验证或升级记录);只满足部分的记为 agent-adjacent。**FEV 三维**(互补且不可互换):**Function**(描述性、非序数):F1 规划与任务分解、F2 角色分工与协调、F3 工具选择与工作流执行、F4 工作流状态维护与 trace 捕获、F5 自评与修复、F6 验证与升级(critic 只有改变了输出才算)。**Evidence**(非序数):E1 文献、E2 结构化生物知识、E3 生物测量与元数据、E4 软件与统计输出、E5 科学模型输出、E6 实验或临床观测;并给出每类的可追溯要求与主要局限(表 S4)。**Validation**(累积门槛,按用例而非平台):V0 示意性输出 → V1 已演示执行 → V2 可重放计算(输入、参数、依赖、中间产物、执行 trace 足以重建)→ V3 科学评估过的计算(在 V2 基础上有任务适当的科学检查)→ V4 前瞻实验评估(对 agent 生成的输出做与主要论断对齐的前瞻检验)。限定符:B 基准/基线、H 协议化专家评估、S 统计/不确定性、R 鲁棒性/失败分析、X 外部独立验证、P 前瞻实验、C 闭环实验改进。关键规则:限定符不能越过未满足的阶段 —— 没有 V2 可重放性就不能凭 benchmark 或专家评估给 V3;已发表的实验数据作为输入属 E6,不是 V4。
<!-- EN --> **Definitions**: distinguishes a bioinformatics copilot (assists user-led analysis), a workflow engine (e.g. Nextflow/nf-core — executes predefined pipelines and can correctly run an inappropriate one) and an agentic bioinformatics layer (adaptive workflow control). A full agentic layer needs goal-directed revisable multistep planning, stateful tool-mediated execution, and inspectable scientific support (evidence, traces, verification or escalation records); partial systems are agent-adjacent. **Three FEV dimensions** (complementary, non-interchangeable): **Function** (descriptive, non-ordinal): F1 planning & decomposition, F2 role specialisation & coordination, F3 tool selection & execution, F4 workflow-state maintenance & trace capture, F5 self-evaluation & repair, F6 verification & escalation (a critic counts only if it changes the output). **Evidence** (non-ordinal): E1 literature, E2 structured biological knowledge, E3 biological measurements & metadata, E4 software & statistical outputs, E5 scientific-model outputs, E6 experimental or clinical observations, each with traceability requirements and limitations (Table S4). **Validation** (cumulative gates, per use case not per platform): V0 illustrative output → V1 demonstrated execution → V2 replayable computation (inputs, parameters, dependencies, intermediate artefacts and traces sufficient to reconstruct) → V3 scientifically evaluated computation (V2 plus task-appropriate scientific checks) → V4 prospective empirical evaluation (prospective test of an agent-generated output aligned with the principal claim). Qualifiers: B benchmark/baseline, H protocol-based expert assessment, S statistics/uncertainty, R robustness/failure analysis, X external/independent validation, P prospective testing, C closed-loop empirical refinement. Key rules: qualifiers cannot override unmet stages — no V3 from benchmarks or experts without V2 replayability; published experimental data used as input is E6, not V4.

## 主要结果 / Key results
<!-- ZH -->
- **整体格局**:规划、工具执行、工作流状态维护、自评/修复普遍存在;角色分工与显式验证/升级(F6)较少。证据以软件输出、结构化知识和回顾性生物数据为主,实验/临床观测(E6)是最少的证据类别。
- **验证阶段**:绝大多数系统为 V3,**只有 7 个达到 V4,没有 V0**;基准比较(B)与鲁棒性分析(R)是最主要的限定符,前瞻检验(P)与闭环改进(C)是例外 —— 闭环实验改进只出现在**一个**被编码的框架中。
- **领域差异**:工具执行与 trace 捕获在病理、药物发现和通用工作流中突出,在基因组学中报告较少;显式验证/升级在基因组学、蛋白工程、单细胞/空间分析中少见;外部评估集中于单细胞、空间与病理系统;前瞻检验集中于蛋白工程。
- **广度 ≠ 保证**:大多数系统实现了多个 Function 与 Evidence 维度,但仍停在 V3;更多 agent、工具、数据库或记忆模块可以扩大工作流,却不建立可重放性、验证或对主要论断的实验支持。
- **最大缺口**(1 − 领域内报告比例):前瞻实验检验与闭环改进最大;验证/升级、专家评估、不确定性分析、外部验证报告不均。
- **示例编码**(补充表):CellVoyager V3 [B,H,R,X],「未报告前瞻湿实验」;SpatialAgent V3 [B,H,R,X],「前瞻湿实验验证未建立」;Biomni V3 [B,R];OmicsNavigator(可审计空间组学假设验证)V3 [B,H,S,R,X],在**肾脏**和肺的 CODEX/IMC 数据集上评估。
- **基准建议**:三类基准互补 —— 结果导向、过程导向、领域校准;正确的终点不应在未调用所需工具、证据捏造或不可重放时得满分;基准报告应写明其结果**不能**支持的论断。
<!-- EN -->
- **Overall landscape**: planning, tool execution, workflow-state maintenance and self-evaluation/repair are widespread; role specialisation and explicit verification/escalation (F6) are less common. Evidence is dominated by software outputs, structured knowledge and retrospective biological data; experimental/clinical observations (E6) are the least frequent category.
- **Validation stages**: most systems are V3, **only seven reach V4, none are V0**; benchmark comparison (B) and robustness analysis (R) dominate the qualifiers, while prospective testing (P) and closed-loop refinement (C) are exceptional — closed-loop empirical refinement appears in **a single** mapped framework.
- **Domain differences**: tool execution and trace capture are prominent in pathology, drug discovery and general workflows but less consistently reported in genomics; explicit verification/escalation is uncommon in genomics, protein engineering and single-cell/spatial; external evaluation concentrates in single-cell, spatial and pathology systems; prospective testing concentrates in protein engineering.
- **Breadth ≠ assurance**: most systems implement multiple Function and Evidence dimensions yet remain at V3; more agents, tools, databases or memory modules expand a workflow without establishing replayability, verification or empirical support for the principal claim.
- **Largest gaps** (1 − within-domain reporting share): prospective empirical testing and closed-loop refinement; verification/escalation, expert assessment, uncertainty analysis and external validation are unevenly reported.
- **Example codings** (supplement): CellVoyager V3 [B,H,R,X], "no prospective wet-lab testing reported"; SpatialAgent V3 [B,H,R,X], "prospective wet-lab validation is not established"; Biomni V3 [B,R]; OmicsNavigator (auditable spatial-omics hypothesis validation) V3 [B,H,S,R,X], evaluated on **kidney** and lung CODEX/IMC datasets.
- **Benchmark recommendations**: three complementary families — outcome-oriented, process-oriented, domain-calibrated; a correct endpoint should not get full credit when required tools were not invoked, evidence was fabricated or the workflow cannot be replayed; benchmark reports should state which claims their results **cannot** support.

## 创新点 / Contributions
- <!-- ZH --> **把工作流轨迹作为分析单元**,并把 agentic bioinformatics 定义为自适应工作流控制层(区别于 copilot 与 workflow engine)。 <!-- EN --> **Workflow trajectory as the unit of analysis**, with agentic bioinformatics defined as an adaptive workflow-control layer (distinct from copilots and workflow engines).

## 局限 / Limitations
- <!-- ZH --> 编码完全依赖论文报告:未报告即不编码,比例描述的是综述样本而非全部文献,且受报告习惯影响。 <!-- EN --> Coding depends entirely on what papers report: unreported means uncoded, and proportions describe the review sample rather than the whole literature and are shaped by reporting habits.
- <!-- ZH --> 是有方法学说明的结构化综述(检索库、关键词、纳排标准),但不是 PRISMA 式系统综述;文中未报告编码者间一致性检验。 <!-- EN --> A structured review with documented methods (databases, search terms, eligibility criteria) but not a PRISMA-style systematic review; no inter-coder agreement check is reported.
- <!-- ZH --> V 阶段是用例级的,同一系统不同任务可能处于不同阶段,跨系统比较需谨慎;作者明确不做排名。 <!-- EN --> V-stages are use-case-specific — the same system may sit at different stages across tasks — so cross-system comparison needs care; the authors explicitly do not rank.
- <!-- ZH --> 是综述/框架论文,FEV 本身没有在真实工作流评测中被实证检验(例如 FEV 分级是否预测下游可靠性)。 <!-- EN --> A review/framework paper: FEV itself is not empirically tested on real workflow evaluations (e.g. whether FEV grades predict downstream reliability).

## 与本研究方向的关系 / Relation to our direction
<!-- ZH --> 这是 **Agent 可信度课题的「概念框架章节」最合适的引用**:它用生物信息学的语言说清了 Agent 可信度课题要做的事 —— 从「答案对不对」转向「工作流对不对」,并把 claim-to-evidence(Evidence 维度的可追溯性)、rerun stability(V2 可重放性)、校准验证(限定符 S/H/X)和失败分析(R)放进同一个结构。具体可用之处:**(1) 给 Agent 可信度课题的评测设一个明确的目标等级**:评估分析肾脏组学(snRNA/snATAC/Xenium)的 agent 时,至少要求 V2(可重放:数据 accession、元数据假设、参数、版本、中间产物、trace),再在 V3 上加 S(不确定性/校准)与 X(在 KPMP/Lake 等外部数据上独立验证);**(2) 证据类别表 S4** 中 E3「生物测量与元数据」的局限 —— 噪声、混杂、批次效应、元数据缺失 —— 正是伪影注入课题「跨模态一致性区分伪影与疾病」要解决的问题:伪影注入课题的输出可以作为 Agent 可信度课题中 E3 证据的**可信度标注**;**(3) detect → model → revert 的 revert 阶段**对应 V4 与 P/C:实验室有湿实验验证能力,意味着我们的系统有机会达到综述中罕见的 V4 [P],甚至 C(湿实验结果回传并改变下一轮提名)—— 这是目前全领域只有一个框架做到的闭环;**(4)** 综述指出单细胞/空间系统(CellVoyager、SpatialAgent)普遍缺显式验证/升级(F6)与前瞻检验,这正是 KidneyAnomalyBench + Agent 可信度课题 verifier 可以填补的定位。另外 OmicsNavigator 在肾脏 CODEX/IMC 上的评估值得跟进,作为与我们最接近的已有系统。
<!-- EN --> The best citation for **the agent-trustworthiness topic's conceptual-framework chapter**: it states in bioinformatics language what the agent-trustworthiness topic sets out to do — move from "is the answer right" to "is the workflow right" — and puts claim-to-evidence (Evidence traceability), rerun stability (V2 replayability), calibrated verification (qualifiers S/H/X) and failure analysis (R) into one structure. Concretely: **(1) a target grade for the agent-trustworthiness topic's evaluation**: agents analysing kidney omics (snRNA/snATAC/Xenium) should at minimum reach V2 (replayable: data accessions, metadata assumptions, parameters, versions, intermediate artefacts, traces), then V3 with S (uncertainty/calibration) and X (independent validation on external data such as KPMP/Lake); **(2) Table S4's limitations for E3 "biological measurements & metadata"** — noise, confounding, batch effects, missing metadata — are exactly what the artifact-injection topic's "cross-modal agreement separates artefacts from disease" addresses: The artifact-injection topic outputs can serve as **reliability annotations for E3 evidence** in the agent-trustworthiness topic; **(3) the revert step of detect → model → revert** corresponds to V4 and P/C: the lab's wet-lab capacity means our system could reach the rare V4 [P], even C (wet-lab results fed back to change the next round of nominations) — a closed loop only one framework in the whole map achieves; **(4)** the review notes single-cell/spatial systems (CellVoyager, SpatialAgent) generally lack explicit verification/escalation (F6) and prospective testing — precisely the niche KidneyAnomalyBench + an agent-trustworthiness-topic verifier can fill.
