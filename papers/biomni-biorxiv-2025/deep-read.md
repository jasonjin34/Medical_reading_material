## 一句话 / One-liner
<!-- ZH --> Biomni 是斯坦福 Leskovec 组的通用生物医学 agent:先用一个 "action discovery agent" 从 2,500 篇 bioRxiv 论文(25 个子领域)里挖出任务/工具/数据库,经人工验证后建成统一环境 **Biomni-E1**(150 个专用工具 + 105 个软件包 + 59 个数据库),再用基于 CodeAct 的 **Biomni-A1**(检索工具子集 → 计划 → 写代码执行 → 迭代)零样本完成跨领域任务,并在一个 CRISPR 克隆案例中做了湿实验验证。它已成为后续生物医学 agent 论文的**默认基线**。
<!-- EN --> Biomni is the Leskovec-lab general-purpose biomedical agent: an "action discovery agent" mines tasks/tools/databases from 2,500 bioRxiv papers across 25 subfields, which after human verification become the unified environment **Biomni-E1** (150 specialised tools + 105 software packages + 59 databases); a CodeAct-based agent **Biomni-A1** (retrieve a tool subset → plan → write and execute code → iterate) then solves cross-domain tasks zero-shot, with one CRISPR-cloning case validated at the bench. It has become the **default baseline** for later biomedical-agent papers.

## 研究问题 / Problem
<!-- ZH --> 已有生物医学 agent 多是为窄任务定制的专用 workflow,难以跨子领域泛化;而通用 LLM 缺少一个**显式定义生物医学动作空间**的环境(工具、数据库、软件、实验 protocol),也缺少能在其中自主组合动作、不依赖预设模板的 agent 架构。作者要回答:能否构建一个"虚拟 AI 生物学家",在遗传学、基因组学、药理、微生物、临床基因组学等多个领域零样本工作。
<!-- EN --> Existing biomedical agents are mostly specialist workflows for narrow tasks and generalise poorly across subfields; general LLMs lack an environment that **explicitly defines the biomedical action space** (tools, databases, software, wet-lab protocols) and an architecture that composes actions in it without hard-coded templates. The question: can one build a "virtual AI biologist" that works zero-shot across genetics, genomics, pharmacology, microbiology and clinical genomics?

## 方法 / Method
<!-- ZH --> **(1) 动作空间发现**:取 bioRxiv 25 个学科类别各最近 100 篇(共 2,500 篇),LLM 分块阅读 PDF,抽取任务、软件、数据库三类可执行要素;过滤到约 1,900 个常见任务后人工去重、剔除"几行代码就能做"的琐碎任务,只保留需领域知识的(湿实验 protocol、AI 预测模型等)。**(2) Biomni-E1**:人类科学家与带网页检索的软件工程 agent 协作实现每个工具,每个工具必须有通过的测试用例,并满足命名/文档/输出为 LLM 友好的研究日志等五项检查;大型关系型数据库(PDB、OpenTargets、ClinVar)各用**一个**自然语言查询函数封装(内部由 LLM 解析 schema 生成查询),无 Web API 的库下载进 data lake 并预处理为 pandas DataFrame;软件装在统一容器里,支持 Python/R/Bash。**(3) Biomni-A1**:基于 CodeAct——先由独立 LLM 做 prompt-based 检索,挑出与问题相关的工具/数据/软件子集(避免长上下文),再生成编号计划,逐步写代码执行、读观察、修正计划,直到收敛。关键设计是**以代码作为统一动作接口**(循环、并行、条件逻辑、非标准函数签名都能表达),而非传统 function-calling。
<!-- EN --> **(1) Action discovery**: the 100 most recent papers in each of bioRxiv's 25 subject categories (2,500 total) are chunk-read by an LLM that extracts tasks, software and databases; ~1,900 recurring tasks are manually de-duplicated and trivial "few lines of code" tasks dropped, keeping expertise-heavy ones (wet-lab protocols, AI predictors). **(2) Biomni-E1**: human scientists plus web-enabled software-engineering agents implement each tool, each required to pass a defined test case and a five-point checklist (name, docs, LLM-readable research-log output, test, non-triviality). Large relational databases (PDB, OpenTargets, ClinVar) each get **one** natural-language query function (an LLM parses the schema and writes the query); API-less databases go into a local data lake as pandas DataFrames; software lives in one container supporting Python/R/Bash. **(3) Biomni-A1**: CodeAct-based — a separate LLM retriever selects the relevant subset of tools/data/software (to keep context short), the agent writes a numbered plan, then iteratively writes and runs code, reads observations and revises until convergence. The key design is **code as the universal action interface** (loops, parallelism, conditionals, non-standard signatures) rather than classic function calling.

## 数据 / Data
<!-- ZH --> **问答基准**:LAB-Bench 的 DbQA 与 SeqQA(45 题开发集用于调接口,315 题留出测试集,三次运行取平均;作者称因 API 成本只取全基准的 12.5%)、HLE 生物/医学 14 个子学科共 52 题(无开发集)。**8 个自建真实任务**:变异优先级(Open Targets Genetics)、GWAS 因果基因(Shringarpure et al.)、CRISPR 扰动筛选设计(Schmidt et al.,IL-2 screen,18,939 候选基因)、罕见病诊断与患者基因优先级(MyGene2 / Alsentzer et al.)、药物重定位(Huang et al.,以 EHR 中临床医生的 off-label 处方模式为对齐标准)、scRNA-seq 细胞注释(CellxGene 等,20k–50k 细胞)、微生物组差异丰度(5 个数据集)。**案例**:30 人可穿戴数据(458 个 Excel、CGM + 体温,另有 10 人 227 晚睡眠、脂质组 652 / 代谢组 731 / 蛋白组 1,470 特征)、人胚胎骨骼发育 snRNA+snATAC multiome(约 336,000 细胞核,5–11 周)、克隆基准与 B2M sgRNA 湿实验。
<!-- EN --> **QA benchmarks**: LAB-Bench DbQA and SeqQA (45-question dev set used to tune interfaces, 315 held-out test questions, averaged over three runs; the authors say they used a 12.5% subset because of API cost) and a 52-question HLE subset across 14 bio/med subfields (no dev set). **Eight new real-world tasks**: variant prioritisation (Open Targets Genetics), GWAS causal gene (Shringarpure et al.), CRISPR screen design (Schmidt et al., IL-2 screen, 18,939 candidate genes), rare-disease diagnosis and patient gene prioritisation (MyGene2 / Alsentzer et al.), drug repurposing (Huang et al., scored against clinicians' off-label prescribing in an EHR), scRNA-seq annotation (CellxGene etc., 20k–50k cells), microbiome differential abundance (5 datasets). **Case studies**: wearables from 30 people (458 Excel files, CGM + temperature; plus 227 nights of sleep from 10 people and 652 lipid / 731 metabolite / 1,470 protein features), a human embryonic skeleton snRNA+snATAC multiome (~336,000 nuclei, 5–11 weeks), a cloning benchmark and a B2M sgRNA wet-lab run.

## 主要结果 / Key results
<!-- ZH --> **LAB-Bench**:DbQA **74.4%**(人类专家 74.7%,ReAct+Code 40.8%);SeqQA **81.9%**(人类 78.8%)。**HLE 子集**:**17.3%**(base LLM 6.0%、coding agent 12.8%、literature agent 12.2%)。**8 个真实任务**(底座 Claude Sonnet 3.7):相对 base LLM 平均相对提升 **402.3%**、相对 ReAct+Code **43.0%**、相对自身 ReAct 消融版 **20.4%**——说明"代码式计划 + 环境落地"是主要贡献来源;每个任务平均 6–24 步,调用 0–4 个专用工具、1–8 个软件包、0–3 个 data lake 条目。**案例**:可穿戴数据中报告餐后体温平均升高 2.19°C(中位 1.10°C,个体间 −0.11 到 15.56°C);multiome 上自主跑完 10 步 pySCENIC/GRNBoost2/cisTarget/AUCell + ATAC 过滤的 GRN 流程(约 5 小时),复现 RUNX2 等已知调控,并提出 AUTS2、ZFHX3、PBX1 在多个骨骼谱系中高活性(作者也承认 PBX1 本是已知骨骼调控因子);克隆基准中盲评专家认为 Biomni 与资深人类专家准确度/完整度相当、明显优于受训者;B2M sgRNA 克隆按 Biomni protocol 原样执行,两个挑选克隆 Sanger 测序完全比对。
<!-- EN --> **LAB-Bench**: DbQA **74.4%** (human experts 74.7%, ReAct+Code 40.8%); SeqQA **81.9%** (humans 78.8%). **HLE subset**: **17.3%** (base LLM 6.0%, coding agent 12.8%, literature agent 12.2%). **Eight real-world tasks** (Claude Sonnet 3.7 backbone): average relative gain of **402.3%** over the base LLM, **43.0%** over ReAct+Code and **20.4%** over its own ReAct ablation — code-centric planning plus environment grounding carry most of the gain; tasks take 6–24 steps using 0–4 specialised tools, 1–8 packages and 0–3 data-lake items. **Cases**: wearables — mean post-meal temperature rise 2.19°C (median 1.10°C; range −0.11 to 15.56°C); multiome — an autonomous 10-step pySCENIC/GRNBoost2/cisTarget/AUCell + ATAC-filtering GRN run (~5 h) that recovers known regulation (e.g. RUNX2) and flags AUTS2, ZFHX3, PBX1 as broadly active across skeletal lineages (the authors note PBX1 is already a known skeletal regulator); cloning — blinded review rates Biomni on par with a senior human expert in accuracy/completeness and clearly above a trainee; the B2M sgRNA protocol executed verbatim yielded two picked colonies with perfect Sanger alignment.

## 创新点 / Contributions
- <!-- ZH --> **从文献自动挖掘动作空间**,再人工验证成可执行环境——把"环境构建"变成可扩展流程,而非手工列工具。 <!-- EN --> **Mines the action space from literature** and then human-verifies it into an executable environment — environment building as a scalable pipeline rather than hand-listed tools.
- <!-- ZH --> 大数据库"一库一函数 + LLM 生成查询"的封装方式,显著压缩工具数量。 <!-- EN --> "One function per database + LLM-generated query" wrapping, which keeps the tool count manageable.
- <!-- ZH --> 代码即动作(CodeAct)+ 检索式工具选择 + 自适应计划,在多领域零样本任务上系统性地优于 ReAct 式链式调用。 <!-- EN --> Code-as-action (CodeAct) + retrieval-based tool selection + adaptive planning, systematically beating ReAct-style chaining zero-shot across domains.
- <!-- ZH --> 少见的**湿实验闭环验证**(克隆 protocol 原样执行并测序确认)。 <!-- EN --> A rare **wet-lab closed-loop check** (cloning protocol executed verbatim and sequence-confirmed).
- <!-- ZH --> 开源代码、Harvard Dataverse 数据与 Web 界面,降低了作为基线复用的门槛。 <!-- EN --> Open code, Harvard Dataverse data and a web UI, making it easy to reuse as a baseline.

## 局限 / Limitations
- <!-- ZH --> 作者自陈:评测任务只覆盖领域的一个子集;动作发现只取"最近"文献,可能遗漏经典方法;在需要临床判断、新实验推理、深度综合的任务上仍不及专家。 <!-- EN --> Self-reported: tasks cover only a subset of the field; action discovery uses only recent papers and may miss classic methods; still below experts on tasks needing clinical judgement, novel experimental reasoning or deep synthesis.
- <!-- ZH --> **评测粒度粗**:LAB-Bench 只用了 12.5% 子集;8 个真实任务多为单底座模型,结果主要以相对提升呈现;多个案例的"新发现"(如新 TF、睡眠规律)只经作者"人工核对 trace 和代码",未做独立验证。 <!-- EN --> **Coarse evaluation**: only a 12.5% LAB-Bench subset; the eight real tasks mostly use one backbone and are reported as relative gains; case-study "discoveries" (new TFs, sleep patterns) are checked only by the authors reading traces and code, not independently validated.
- <!-- ZH --> 文中克隆基准规模前后不一(结果部分写 10 个任务、方法部分写 20 个开放问题与三位专家),阅读时需留意。 <!-- EN --> The cloning benchmark is described inconsistently (10 tasks in Results vs. 20 open-ended questions and three experts in Methods).
- <!-- ZH --> **没有不确定性、可复现性或声明-证据核查机制**:agent 输出的结论没有置信度,也没有重跑稳定性分析。 <!-- EN --> **No uncertainty, rerun-stability or claim-to-evidence checking**: conclusions carry no confidence and run-to-run stability is not analysed.
- <!-- ZH --> 后续独立评测显示其上限有限:HeurekaBench 中它虽是三个单细胞 agent 里较强的,开放题正确性也只有约 2.3–2.6/5;SpatialAgent v2 的心脏 MERFISH 注释中它出现 label collapse(偏向内皮细胞,总体准确率 0.394)。 <!-- EN --> Later independent evaluations show a limited ceiling: in HeurekaBench it is among the stronger of three single-cell agents yet scores only ~2.3–2.6/5 on open-ended correctness; in SpatialAgent v2's heart MERFISH annotation it shows label collapse toward endothelial cells (overall accuracy 0.394).

## 与本研究方向的关系 / Relation to our direction
<!-- ZH --> Biomni 处在 detect → model → revert 链条的**分析执行层**:它本身不做异常检测,也不建 virtual tissue,但它是"让 agent 跑完一套组学分析并给出生物学结论"的事实标准基线。对 **Plan B(可信生物医学 agent)** 最直接:它是我们要审计的典型对象——一个会自主写代码分析肾脏 snRNA/snATAC/Xenium、然后输出"新调控因子 / 新规律"式声明的系统,而它恰恰**没有**声明-证据核查、没有校准置信度、没有重跑稳定性评估;其 multiome 案例(snRNA+snATAC GRN、靠人工读 trace 来判断是否幻觉)几乎就是 Plan B 想自动化的那个"verifier"场景,可直接借来构造肾脏版任务:让 Biomni 在 KPMP/Lake 数据上跑 GRN 或差异分析,再用我们的 verifier 逐条检查结论是否被数据支持、多次重跑是否一致,并按组学特有失败类型(批次/环境 RNA 被当成生物信号、单模态推断调控等)建分类。对 **Plan A** 的价值是间接的:Biomni-E1 的"一库一函数"和 data lake 设计可作为把 KidneyAnomalyBench、KPMP/HuBMAP 参考数据接入 agent 环境的工程模板;但要警惕它在空间注释上的 label collapse——在异常检测场景下,这种系统性偏置会把真正的病灶细胞态"吞"进常见类别。对 revert 阶段,它的 CRISPR 筛选设计任务(从 ~19k 基因中选扰动集)和湿实验克隆闭环,是"agent 提名扰动 → 湿实验验证"这条路在工程上可行的一个早期样例。
<!-- EN --> Biomni sits at the **analysis-execution layer** of detect → model → revert: it neither detects anomalies nor builds a virtual tissue, but it is the de-facto baseline for "an agent that runs an omics analysis end-to-end and emits a biological conclusion." It matters most for **Plan B (trustworthy biomedical agents)**: it is the archetypal system to audit — one that autonomously writes code over kidney snRNA/snATAC/Xenium-like data and outputs "novel regulator / novel pattern" claims, yet has **no** claim-to-evidence checking, no calibrated confidence and no rerun-stability analysis. Its multiome case (snRNA+snATAC GRN, with hallucination judged by humans reading traces) is almost exactly the "verifier" setting Plan B wants to automate; it can be ported into kidney tasks: run Biomni on KPMP/Lake data for GRN or DE analysis, then have our verifier check each claim against the data, measure agreement across reruns, and file failures into an omics-specific taxonomy (batch/ambient RNA read as biology, regulation inferred from one modality, etc.). For **Plan A** the value is indirect: Biomni-E1's one-function-per-database and data-lake design is an engineering template for plugging KidneyAnomalyBench and KPMP/HuBMAP references into an agent environment — but its label collapse on spatial annotation is a warning, since in anomaly detection such systematic bias would absorb genuine lesion cell states into common classes. For the revert stage, its CRISPR screen-design task (choose perturbations from ~19k genes) and the wet-lab cloning loop are an early demonstration that "agent nominates perturbation → bench validates" is feasible as engineering.
